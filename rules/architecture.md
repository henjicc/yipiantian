# 架构与代码组织

> 读取时机：引入抽象、通用封装或依赖，改变模块职责、依赖方向、公共契约、状态归属或跨层边界时。

## 职责与权威入口

- 先定位真实调用链、数据源和消费者，再决定修改位置；优先沿用项目已有结构。
- 同一业务规则、schema、状态和能力定义只维护一个权威来源，其他入口通过委托或派生复用。
- 展示负责呈现和输入，核心规则不依赖具体 UI；外部存储、网络和供应商细节放在明确边界。只在实际复杂度需要时引入应用层、领域层、adapter 等结构，不机械建立四层目录。
- 临时 UI 状态留在局部；共享与持久化状态明确权威修改者，派生缓存明确失效和重建条件。
- 仅外形相似、变化原因不同的代码不强行合并；不为消除少量重复引入更多模式参数和条件分支。公共接口按真实消费者需要保持最小。

## Godot 游戏边界

- GDScript 使用类型标注并遵循官方风格；节点与场景按实际职责组合，紧密相关脚本与场景可放在一起。不默认增加 Autoload、全局事件总线、对象池或第三方测试框架。
- 作物和地块的权威状态独立于场景对象、动画、材质与输入；视觉从状态派生，不通过模型大小、颜色或对象是否可见反推生长和奖励。
- 时间推进、玩法动作与持久化职责清晰；时间与恢复规则见 [farm-simulation.md](farm-simulation.md)。可用简单类或函数实现，不为未来宿主预建 ECS、事件总线、多进程或通用插件框架。
- 使用 Resource / `.tres` 等配置资产时，区分设计期定义与玩家运行状态；不得把共享配置资产直接当作可变玩家存档。
- Windows 窗口控制仅在对应能力进入范围后实现，并与核心玩法隔离；当前不需要为未建立的宿主创建接口占位或空工程。
- `Game/` 中使用文本场景 `.tscn` 和资源 `.tres`；保留脚本 / Shader 的 `.uid` 与资产旁的 `.import`。移动、重命名优先走 Godot 文件系统面板；直接改文件时同步检查路径、UID 和所有引用，不能把重建缓存当成引用一定恢复。导入缓存和构建产物不手改或提交。Blender 源文件放 `ArtSource/`，Godot 使用显式导出的 GLB；目录与试验边界统一见 [README](../README.md)。
- 外部模型进入工程前统一比例、朝向、枢轴、材质和生长阶段衔接；优先验证当前资产在目标渲染管线中的效果，不预建完整资产流水线或默认引入对象池。
- `docs/ref/` 是被忽略的本地资料区，运行、测试和构建不得从中读取必要数据。实际采用的模型、贴图和配置应进入正式资产目录；保留必要源文件、来源及使用依据，不让未提交的本地素材成为隐性依赖。
- Tripo 等生成工具只是候选资产来源，不是工程启动依赖；先用一个资产验证导出、材质、比例与 Godot 导入，再决定是否自动化。Blender 源文件与导出给 Godot 的模型分清用途，避免开发和构建机器依赖未声明的本机转换工具。
- Godot CLI、Blender MCP 等执行工具属于开发环境边界，限定明确工程及本机连接；不作为农场玩法依赖，不在正式发布产物中启用通用远程代码执行入口。锁定实际验证的工具版本，读取执行结果与产物，不只依据命令顶层成功标记。

## 可信与跨进程边界

- 当前按本地单机游戏划分输入、存档和系统能力边界，不虚构服务器、认证或反作弊层；若以后加入远端能力，再确定可信执行位置。
- 校验放在真实输入或可信边界；同一可信边界内已由类型、解析或调用契约保证的条件，不逐层重复防御。不同权限、阶段或业务不变量的检查仍须保留，静态类型不能证明外部输入可信。
- 有远端服务时通过明确 API / schema 通信；无远端服务不虚构后端。桌面应用通过具名、受限、可校验的桥接访问宿主能力，不暴露原始 IPC 或通用执行入口。
- 共享契约而非供应商响应或存储内部模型；边界负责转换及错误语义。长任务按需要明确取消、重试、幂等、超时和迟到结果处理。

## 复用与依赖

- 先查现有实现、标准库和已有依赖；复杂成熟能力再比较外部方案与自研成本，按研究规则核验许可、维护、兼容及关键行为。
- 简单局部逻辑优先直接表达或使用具名函数；不为单个简单分支建立注册表、策略框架或通用执行器，不增加无独立职责的透传包装层。
- 抽象应简化当前复杂逻辑、统一真实规则或隔离实际边界；差异确由数据或能力决定时再集中配置或策略。一次使用的辅助函数、单一实现的接口也可有这些价值，不机械按复用次数决定。
- 引入依赖应有当前收益，并计入集成、升级和替换成本；第三方边界的隔离程度与实际风险匹配，不为每个依赖统一套一层。

## 变更边界

- 重构仅在用户要求，或为本次功能实现、根因修复所必需时进行；限于相关代码，不扩展到无关模块。高影响迁移先建立行为基线，迁移消费者后移除旧路径。
- 必要兼容路径明确退出条件，不保留无期限双轨实现。
- 长期且不易从代码推断的决策写入项目既有决策入口；局部细节不另建 ADR，注释解释原因而非复述代码。
- 架构事实变化时同步上下文和受影响规则，不把未经批准的扩展写成既定架构。
