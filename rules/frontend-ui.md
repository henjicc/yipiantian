# 游戏界面、三维视觉与文案

> 读取时机：修改游戏界面、镜头、场景视觉、模型规范、文案或交互时；只应用与本次变化相关的条款。

## 沿用系统与产品形态

- 沿用已确认的产品形态和设计系统；改变平台行为时再读取平台规则。
- 沿用现有 Godot Control、材质、组合场景和配置入口；尚无工程时不默认锁定 UI 技术。共享颜色、字体、控件尺度与反馈保持一致，不为单个控件搭建完整设计系统。
- 用户指定全部游戏文字使用内置汇文明朝体，资源为 `Game/art/ui/fonts/汇文明朝体.ttf`；全局默认、共享主题与独立文字节点保持一致，不改用系统字体。中文文件名已验证可用；来源与历史字体见 `ArtSource/UI/README.md`。
- 场景是视觉主体，UI 服务照料和布置操作；避免以大型面板遮住农田。视觉方向见项目上下文，具体风格在实际画面中验证。
- 作物阶段、工具与装饰保持一致的比例、轮廓、材质和枢轴约定。离散生长阶段允许 Tripo 独立生成或由生成部件组装，不强制同拓扑；核对品种、根部、体量和色彩连续性。只有确需连续形变时再约束拓扑或骨骼。
- 制作、生成或批量替换三维资产前，按 [资产工具分工](../docs/asset-workflow.md) 判断尺寸拼接、阶段连续性、动画和修改需求，再选择 Blender、Tripo 或 Godot 的对应环节。技术接入成功不等于资产可用；按目标镜头与用途验收。具体分工、生成模型选择及试样方法在该文档维护，不重复复制工具清单。
- 替换模型或调整场景摆件后，检查与相邻模块的实际空间关系：柱子与桌面／簸箕、桌腿与篮子、家具与栏杆／墙体，以及脚底与承载面。除全景外至少从两个相反侧向近看受影响接触区域，确认没有穿模、悬空或重复叠放；单体模型审计、面数正确或全景好看不能替代组合场景检查。发现问题先修布局，再交付最新可交互预览。
- 使用 Tripo 生成或处理资产前，先读 [Tripo 能力与工作流](../docs/tripo-workflow.md) 的相关条目，主动按质量问题选择几何、纹理、多视图、分件等能力并核对本次接口；不机械沿用旧参数。复用已核验资料，只对版本变化、未覆盖能力或冲突定向补查；实测后维护原条目，不反复从头调研，也不把官方能力说明当成本项目效果保证。
- 所有 Tripo 模型生成先调用图片生成工具制作并检查单体参考，再图转模型；多种形态分别出多张图，不直接文字转模型。必须执行[完整生产流程](../docs/asset-workflow.md#工具之间怎样交接)：用途与参考 → 模型及参数选择 → 生成与原件保存 → 必要后处理 → Godot 接入 → 实景验证 → 留档与交付。每件资产记录实际使用的几何／纹理／后处理模型版本、选择理由、参数、任务与费用、处理顺序、正式落点及验证结果，不能只记“用 Tripo 生成”。记录字段和存放位置以该流程及其[留档要求](../docs/asset-workflow.md#本地制作留档)为准；未执行的可选步骤明确标注不需要或未执行，不增加逐步审批。

## 江南微缩田园参考

- 当前美术参考围绕灰瓦粉墙、旧木、竹篱、青石、陶器、菜畦与水岸形成生活气息；青绿、土色和少量暖灯作色彩线索。原型可用简单几何体先验证比例、构图和操作，不要求一次制作整套精细资产。
- 场景尺度以农家院落为参照，避免欧式红谷仓、荷兰风车、宫殿化或仙侠悬浮建筑作为默认资产。图板中不一致的单个对象不推翻文字提炼的风格；采用严格历史设定时另行核验年代。
- 普通概念图用于构图、体块、色彩与氛围参考，不自动成为功能范围或实时画质保证；首个可发布版本中用户指定的主界面图已明确成为整体视觉验收依据，须按任务方案在实机对照，不降为仅供灵感。先在目标窗口中验证田地和作物可辨识，再增加瓦片、花草、水面和后处理细节。
- 运行画面参考、结构输入与笔触材质参考分别注明用途；图转模型前检查完整轮廓和部件连接，不直接提交整张场景图板，也不把水墨断笔误当几何破洞。阶段作物保持同一品种与结构来源。当前入口为 [制作基准包](../docs/design-baseline/README.md)，图片入库不代表获选或三维验收通过。
- 用户已确认 A 工笔淡彩全景 + A 淡彩青菜：造型圆润简洁，细线与淡彩色斑保留自然层次，避免摄影级叶脉、纹理和破损，也不抹成光滑塑料。生成与建模前使用 [固定图与提示词](../docs/design-baseline/style-guide.md)，不把历史 B / C 图或此前推荐替代获选基准；随机生成仍须对照检查。
- 保留卡通轮廓与自然材质的层次，避免塑料高光、均匀高饱和度和满屏琐碎装饰；不把低多边形数量本身当成美术目标。
- LOD 必须随实际屏幕大小保留可见细节，禁止把全景、非选中对象或低画质统一设为 `lod_bias=0`（会锁到最简网格）。新增／替换模型、修改减面或动态权重时，执行[LOD 与破面验收流程](../docs/asset-workflow.md#lod-与破面验收)，检查原件、导出和运行时各层；不可用全局关闭 LOD 或单纯增加面数代替定位。人工低档不得未经检查再叠加自动减面。
- 图片出现人物和动物，不自动要求可操控角色、寻路、村民关系或养殖系统。参考目录缺失时依据项目上下文与本规则继续；只有需要精准比对原图时才索取缺失素材。

## 镜头、清晰度与布局

- 间距表达关系；组件管理内部间距，父布局管理组件之间的间距，避免重复留白。
- UI 布局检查目标窗口尺寸、宽高比和 DPI 缩放；避免硬编码单一分辨率，也不为未承诺的移动端增加适配。
- 不用空白字符、重复换行、无意义占位或不断提高渲染排序修补布局；明确 UI、场景对象和输入命中的层级关系。
- 优先用间距和排版分组，必要时用分隔线或容器；不堆叠卡片、边框、阴影和无目的动效。
- 状态不能只靠颜色表达；选中、可操作范围和无效落点应有清晰的形状或标记反馈。夜间和阴影下仍须看清当前操作对象，不因现实时间同步让核心操作不可用。
- 当前已明确全景浏览、点击田块平滑聚焦与视角微调；默认镜头体现完整农场的斜向立体层次。全景负责选择田块，聚焦后进行种植，相机转动、平移、缩放不得与工具输入争抢或在移动结束后补执行旧操作。返回全景应恢复可理解的位置，角度和距离限制、遮挡与边界按实际场景验证；不因此自动新增角色移动或无限自由相机。
- 已授权的 Debug 自由视角：滚轮缩放，左键按下时取点击表面作为固定旋转中心，中键或右键拖动平移；不触发农事或右键返回。普通视角也支持滚轮缓入缓出缩放，最远为当前全景／聚焦／布置模式的初始距离，可以向内放大。连续滚动累计目标；UI、失焦及取消边界不得残留拖动或补执行农事输入。普通模式既有右键取消、中键微调保持独立。
- 景深服务微缩感，不能遮蔽判断所需的信息。选中、拖动和摆放目标保持清晰；若存在观赏、交互、编辑模式，按任务调整景深，不为了三套景深参数专门新增三种模式。
- 用户已明确允许全景中的镜头相对前景植物，不要求它们严格对应院落真实空间；用于画面边缘框景与近景虚化。前景须避开田块、布置目标和界面，聚焦与布置时平滑退让，并尊重既有景深和画质偏好。参考图的氛围验收包括可见而轻柔的树叶、草和作物风动、湖面碎波反光、船体起伏以及独立远云运动；静态模型存在或着色器编译通过不能代替动态实景检查。

## 文案与说明

- 选项、设置、按钮等控件的补充性描述、副标题、说明小字、helper text 或 tooltip，只有用户明确要求时才能在要求范围内新增或扩写。要求新增功能、选项或优化界面，不等于要求增加说明文案。
- 未明确要求时直接省略此类说明，优先用准确标签和合适控件表达用途；不能因“有帮助”“更完整”或“怕用户不理解”自行添加，也不能转移到 placeholder、信息图标或其他位置变相添加。
- 获准添加的说明必须面向产品用户，用简短、自然的语言表达操作、结果或用户关心的后果；不使用开发者口吻，不讲内部协议、算法、日志、技术实现或设计过程。标签已表达清楚的内容不再复述。
- 控件标签、实际运行状态、校验错误和操作结果仍按交互需求提供，并使用面向用户的语言；不能把功能介绍或实现解释包装成状态、错误或提示来绕过上述限制。placeholder 不能替代标签。

## 组件与交互

- 先搜索已有控件和语义变体，再新增公共组件；不为一次使用过早抽象，也不复制同一控件的行为和样式。
- 展示组件表达数据与意图，业务规则和特权能力通过项目正式入口调用；不因 UI 改动另建平行状态源。
- 控件有可理解标签；实际支持的键盘操作有可见焦点，加载、错误、禁用与成功反馈保持一致。不为满足形式给每个三维动作另造一套键盘系统。
- UI 命中与地块 / 工具输入互斥；拖动、取消、无效放置和失焦恢复有明确结果。视觉反馈与权威玩法状态一致，不把播放动画当作操作成功。
- 场景卸载或异步加载时防止旧结果覆盖新状态；危险动作按可撤销性和授权边界处理。
- 动效解释生长和操作结果，避免持续抢注意的闪烁、镜头晃动或密集提示；尊重已有减少动效偏好，不因此自动新增设置系统。性能问题先测量，再选择合批、实例化、对象池或其他优化。

验证范围由测试规则统一决定。局部文案不触发全场景检查；共享材质、控件或镜头变化才覆盖相关消费者。
