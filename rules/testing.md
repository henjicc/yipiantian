# 验证与完成标准

> 读取时机：决定验证范围、验证改动或交付运行结果时。

## 按风险选最小充分证据

| 级别 | 行为变化 | 验证范围 |
|---|---|---|
| L0 | 不改变运行行为的文档、规则、注释 | 格式、路径、引用及指令一致性；不跑无关构建 |
| L1 | 局部低风险逻辑、样式、文案 | 最近的相关测试或静态检查，以及受影响的可见行为 |
| L2 | 公共契约、共享状态、权限、持久化、I/O、并发 | 直接和相关测试、受影响工程检查、对应失败与边界场景 |
| L3 | 影响面无法界定的重构、核心依赖或基础设施变化、发布、用户明确要求全量验证 | 项目约定的全量检查、构建和必要冒烟 / 端到端验证 |

在完整切片首次可验证时执行相关检查；失败先定位，不用更大测试集掩盖。相关验证通过且边界清晰后进入交付，只有新增改动、失败或风险证据才复跑或扩大范围。不要重复执行已被其他命令包含的检查。

当前阶段以快速迭代为目标。执行前指出本次具体改变与最小验证入口；优先一条有针对性的功能检查加必要画面观察。已有定向集覆盖时不再叠加完整场景、全资产、长时间性能或重复截图巡检；扩大范围必须有新失败、受影响的共享行为或用户明确要求。没有数据格式／读写变化不测存档；不新增旧数据兼容测试。测试数量不是交付质量指标，最终报告结论和必要限制即可。

## 何时新增测试

- 必要验证不等于每次新增测试。先确认行为变化与现有覆盖缺口；低风险、可逆且已有充分证据的改动，不为完成形式新增测试文件、框架或门禁，仍执行匹配的相关检查。
- 新测试应能指出要防止的具体错误，并在该错误出现时失败；优先覆盖变化的行为、缺陷回归和真实边界，不为测试数量或覆盖率数字堆案例。项目既定门禁仍须满足，不能以精简为由削弱断言或关闭检查。
- 在能可靠发现问题的最小层级补测；不同层级分别验证自身风险，不在单元、集成和端到端层机械复制同一组场景。按有区别的行为和风险选择边界，不穷举无依据的参数组合。

## 证据质量

- 验证用户可观察行为和稳定契约，不镜像实现、堆无意义快照或重复类型系统已保证的事实。不锁定私有字段、内部函数拆分或无契约意义的调用顺序；次数、顺序本身是契约时仍须验证，如只扣款一次。
- 缺陷修复尽量取得稳定失败证据，在合适层补回归测试；验证修复前失败、修复后通过，无法反证时说明替代证据。
- mock 只替代需要隔离的依赖边界，不复刻或绕过被测规则；优先使用简单真实对象或项目已有测试替身，不为方便 mock 给生产代码增加无其他价值的接口、配置或分层。
- 测试数据和辅助函数以让单个用例清楚呈现输入、动作和结果为准；可保留少量直观重复，不为去重建立复杂的 fixture 继承、通用 DSL 或测试专用框架。
- 涉及并发、重试、取消或恢复时，验证迟到结果、重复操作、部分完成和最终权威状态；不要只断言命令成功或事件已发出。
- 新增自动门禁时，在隔离样例或安全可恢复环境构造目标错误，确认检查确实能阻止它。
- 本地检查不等于 CI 已通过；测试、构建产物、运行实例、远端交付分别核验，只执行任务承诺且获授权的层级。

## 规则变更验证

除链接和格式外，按修改涉及的条款及相邻规则走查正常、边界和不应触发的任务，确认没有误触发、停顿或越权。涉及初始化、权限或 Git 流程时，再覆盖受影响的 `pending` / `ready`、状态缺失 / 非法、中断、模板维护、只读、无上游或已有用户改动场景；初始化完成才切换状态，后续更新不会重复初始化。

上述走查是文本逻辑验证，不能宣称已证明模型在实际会话中必然遵循；若需要行为可靠性证据，用隔离项目执行代表性任务，不污染模板状态。

## UI 验证

本机交付开发预览默认静音、右侧第二块显示器、**真正全屏而非窗口最大化**。2026-09-17 实测该屏是 Godot 索引 **0**（不是 1），物理位置 `(3840,0)`、3840×2160；主屏索引 1。普通 `scripts/godot.ps1 -Action Run` 自动使用全屏开发入口；带 `--script`／`--headless` 的隔离测试保持自身窗口要求，不触发交付实例重启。录制入口默认 `-Screen 0` 且静音播放。布局变化时先重新枚举，不按 Windows 显示器编号猜 Godot 索引。用户在主屏操作时不为性能测量抢焦点；失焦样本不能当作前台性能结论。

按变化选择：文案检查可理解性和受影响布局；工具交互检查命中、拖动、取消、失焦与错误路径；共享控件、材质或镜头检查受影响场景、窗口尺寸和昼夜可读性。使用真实内容及相关极端场景，编译通过不能替代画面和操作验证。不要求局部改动遍历无关场景与状态。

## Godot 与农场验证

- 入口见 README 与开发准备。修改脚本可用 `--headless --check-only --script <脚本>` 检查语法，但不能把它当成全工程检查；资源与场景改动按需 `--import` 并运行受影响场景。首次克隆或缺少缓存先导入。检查退出码、错误日志与实际产物，未知 CLI 参数可能被静默忽略。
- 纯规则计算优先用可控时间验证；Godot 节点、场景生命周期与输入集成使用实际场景运行或匹配的测试入口，不要求所有改动同时覆盖全部层级。模拟与存档具体判据见 [farm-simulation.md](farm-simulation.md)。
- 场景、Resource 或模型改动检查丢失引用、碰撞 / 射线命中和实际视觉；资产导入成功不能代替玩法或画面验收。
- Windows 构建、窗口与系统集成改动需要相应独立程序验证，不能以编辑器中运行正常替代。未取得目标环境时说明未验证的边界。
- 涉及性能或后台行为时，在可辨识的硬件、分辨率、场景规模和前后台条件下记录 CPU / GPU 帧耗时、内存等相关指标；不能只凭低 FPS 宣称低资源占用。预算按当前阶段确定，不将材料中的参考值当作实测达标。
- 主观体验验证区分作者观察与玩家反馈；画面截图不能证明玩家会因阴影调整布局或愿意次日回访。只有任务包含体验调研时才开展对应活动。

## 关键节点录屏

- 用户要求保留可剪辑的制作过程，但最新要求是**只有很有必要时才录屏**：用户明确要片、不可复现的关键过程，或必须用动态对照说明的重大变化。首个成果、资产接入或阶段验收本身不自动触发录屏；普通回归和反复排错不逐次录制，不持续录屏，也不为拍摄延迟必要开发。
- 可从保存源文件重现的展示可先登记节点、截图和补拍入口，后续按视频需求集中补拍；同类效果已有录像时复用，不让每次小改动都附带数分钟4K录制。不可重现的关键过程及时留存，用户明确要求本次成片时完成相应录制。
- **镜头节奏（2026-09-21用户修订）**：脚本明确写了停顿时长就遵循脚本；未明确时，成片开头默认约0.5秒、不得超过1秒，准备、加载和预滚从交付片中裁掉。此上限只约束开头，不扩展到中途或结尾；原收尾至少3秒的余量在脚本无其他要求时保留。模型旋转展示默认逆时针、4°/秒（5秒转20°），主体水平垂直居中，鸡等动物以完整身体轮廓居中，上下留出空间，整个走路和旋转过程中不贴边、不裁脚；骨架、蒙皮与模型检查面板素材同样适用。骨骼模型须以实际姿态判断轮廓，不能直接用未经蒙皮变换的网格包围盒定位。用户明确指定时覆盖，运镜默认先快后慢（ease-out），接近终点连续减速至零，不能匀速后突然停住；必要的起步缓冲应短，不让长缓动形成新的开头等待。通常小角度环绕10–20°；需要揭示侧背结构时给足转角。不要把日常交互改慢或为拍摄增加玩法。
- **字幕素材余量（2026-09-22）**：不能把源片精确裁成字幕长度；前后各至少留1秒可用画面，余量可以处于运动中，不用静止等待充数。约9秒的口播可制作12秒素材；多项操作按当前讲解合理分配，开头立即进入有效动作。变速使用时按实际剪辑速度换算源余量。
- **运动中的过渡与收尾（2026-09-21用户反馈）**：同镜头的贴图／实体／网格等显示状态默认用不透明度交叉渐变衔接，过渡期间继续运镜，不先停住再切换；两状态使用同一时刻的相机姿态，避免重影错位。推近、拉远、旋转和摇移默认先快后慢，位置与朝向等共同平滑收尾，不能只给推近加缓冲而旋转仍骤停。脚本明确要求硬切、匀速跟随或其他节奏时按脚本执行。验收要播放检查渐变期间的运动和结束前后的速度变化，帧连续不等于缓冲自然。
- **游戏效果由游戏呈现**：展示最终材质、光照、风动、LOD或场景关系时优先复用对应版本Godot工程的真实资源与渲染设置，在隔离副本中增加录制专用相机、跟随及演示状态，不能默认用Blender灯光替代游戏效果。仅展示建模或拓扑时使用Blender；跨工具画面明确标注用途。游戏镜头优先复用 [录制入口](../scripts/record.ps1) 的固定步长输出，按需适配到隔离工程，不能假定现有脚本支持任意工程；不启动会重启主开发游戏的入口。并行修改期间使用固定版本、副本、独立缓存/演示存档及本批脚本，不覆盖主工程或控制他人窗口；无法隔离的文件、窗口或设备占用冲突先暂停并说明。
- **Blender操作展示**：在可确认归属的独立录制实例中打开副本，先核对显示器物理位置与尺寸，再移到用户右侧第二屏并启用整个Blender窗口全屏，录下完整应用界面，保留与讲解相关的视口、属性和操作过程；不要用单一编辑区域全屏冒充整窗全屏。不能把Godot屏幕索引直接用作其他录屏工具的索引。正式拍摄前检查原生4K、窗口归属、界面可读性、鼠标和运动连续性；另一任务占用该屏/实例时先隔离，不能隔离就暂停。本机Blender5.2默认键位中整窗全屏为Alt+F11，实际执行前确认键位未改。
- **四边面讲解必须展示真实拓扑**：从原始FBX或保留原生面的可编辑blend显示实体→网格线→局部面结构，按文稿提供可剪视频；可录Blender完整界面，需要干净线框时另出单独展示片。确保线条清楚，不用贴图网格、人工假线或已三角化GLB冒充原生四边面；网格有三角面/多边面时如实显示，不能称全部四边面。素材表记录对应文稿原句和实际模型版本。
- **捕获范围与格式**：游戏、Blender界面、Godot编辑器和桌面壁纸镜头分别选择已授权的目标窗口/显示器。游戏录制入口仍只捕获游戏，不自动扩大到桌面；Blender整窗与桌面展示使用对应捕获方案。全画面原生3840×2160，默认60fps；游戏自动展示固定步长输出后用NVENC编码H.264，实时窗口捕获须检查重复帧。透明素材交付ProRes4444 MOV并验证实际Alpha；PNG可作内部中间帧。无所需捕获/编码能力时明确说明，不静默放大低分辨率或冒充已验证。
- **集中拍摄与留档**：按场景集中准备，但输出一条或多条取决于连续性、独立用途和规格，不强行拼成长片。本片素材放Git忽略的 `视频制作素材/`，文件使用 `001_素材描述`；拍摄代码、脚本、场景、参数、必要依赖快照、命令、版本、检查与反馈记录保存到其 `制作工程/` 并关联每个输出。既有历史 `制作留档/05_开发录屏/` 保持原位，可按用户要求复制复用。完整演示通过尺寸、编码、帧率、逐帧时间戳和运动连续性检查后加入索引；手动/提前停止片段标明待复核。记录实际工具贡献与剪辑提示，失败片不作成功素材，不自动把工具广告叠在游戏界面中。
- 录屏的 60 fps 是成片时间轴，不是游戏性能通过的证明；不能把自动演示说成用户实测。自动演示的固定步长输出明确标为离线演示渲染；实测性能独立验证。运动区间要检查相邻画面有无异常重复 / 跳变并预览，不能用 FPS 标签、时间戳或静态截图替代；静止停留不应被误判为掉帧。采样区间随镜头脚本更新。

## 开发服务

本项目尚无长期开发服务。改动需要重新加载时直接执行 `scripts/godot.ps1 -Action Run`：入口自动检测命令行项目路径精确匹配的交互式开发游戏，先关闭旧实例再启动新版，无需逐次确认。优先正常关闭；已确认归属的开发实例短时无法退出时可以强制结束。排除编辑器、其他项目、测试和录制进程，不按进程名批量关闭；无法确认归属的进程不猜测关闭。此授权覆盖本项目正在运行的开发游戏，不限本轮启动的PID。

开发入口以临时 `--dev-preview` 覆盖旧窗口偏好，静音、第二屏独占全屏，核验就绪回显、实际窗口和屏幕后保持运行。普通交付不再手写零散启动命令。纯规则／文档改动可保留已确认对应当前代码且符合全屏要求的实例，避免无意义重启；没有实例时启动。仅查询无需启动，用户当次另有要求时优先遵循。

已实测当前大场景可能晚于启动脚本的 45 秒期限才进入就绪状态。该超时不等同于进程退出：先读取本次日志中的 `DEV_PREVIEW_READY`，核对该进程的项目路径、屏幕参数、实际窗口句柄和响应状态；就绪且窗口正常时保留实例，不因脚本超时反复重启。超时路径可能未更新 `.local/dev-preview/current.json`，不能单凭旧状态文件判断当前实例。

上述交付预览也适用于规则或文档改动；纯只读咨询无需启动，用户明确要求不启动时遵循当次要求。启动失败应报告实际原因，不能以进程创建成功替代窗口就绪。涉及真实数据、费用或额外权限时按既有授权边界处理。未来新增长期开发服务时，再按实际入口补充归属识别、就绪、重启和安全停止约定。

最终回复结尾按实际情况选一条：

- `🟢 游戏已启动（静音，第二屏）`
- `🟢 开发服务已启动`
- `🔄 开发服务已重启`
- `✔️无需重启（开发服务保持运行）`
- `⏭️无需启动（本次改动不影响开发服务）`
- `🔴 开发服务启动失败：<原因>`
