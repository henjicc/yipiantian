# 验证与完成标准

> 读取时机：决定验证范围、验证改动或交付运行结果时。

## 按风险选最小充分证据

| 级别 | 行为变化 | 验证范围 |
|---|---|---|
| L0 | 不改变运行行为的文档、规则、注释 | 格式、路径、引用及指令一致性；不跑无关构建 |
| L1 | 局部低风险逻辑、样式、文案 | 最近的相关测试或静态检查，以及受影响的可见行为 |
| L2 | 公共契约、共享状态、权限、持久化、I/O、并发 | 直接和相关测试、受影响工程检查、对应失败与边界场景 |
| L3 | 影响面无法界定的重构、核心依赖或基础设施变化、发布、用户要求 | 项目约定的全量检查、构建和必要冒烟 / 端到端验证 |

在完整切片首次可验证时执行相关检查；失败先定位，不用更大测试集掩盖。相关验证通过且边界清晰后进入交付，只有新增改动、失败或风险证据才复跑或扩大范围。不要重复执行已被其他命令包含的检查。

## 何时新增测试

- 必要验证不等于每次新增测试。先确认行为变化与现有覆盖缺口；低风险、可逆且已有充分证据的改动，不为完成形式新增测试文件、框架或门禁，仍执行匹配的相关检查。
- 新测试应能指出要防止的具体错误，并在该错误出现时失败；优先覆盖变化的行为、缺陷回归和真实边界，不为测试数量或覆盖率数字堆案例。项目既定门禁仍须满足，不能以精简为由削弱断言或关闭检查。
- 在能可靠发现问题的最小层级补测；不同层级分别验证自身风险，不在单元、集成和端到端层机械复制同一组场景。按有区别的行为和风险选择边界，不穷举无依据的参数组合。

## 证据质量

- 验证用户可观察行为和稳定契约，不镜像实现、堆无意义快照或重复类型系统已保证的事实。不锁定私有字段、内部函数拆分或无契约意义的调用顺序；次数、顺序本身是契约时仍须验证，如只扣款一次。
- 缺陷修复尽量取得稳定失败证据，在合适层补回归测试；验证修复前失败、修复后通过，无法反证时说明替代证据。
- mock 只替代需要隔离的依赖边界，不复刻或绕过被测规则；优先使用简单真实对象或项目已有测试替身，不为方便 mock 给生产代码增加无其他价值的接口、配置或分层。
- 测试数据和辅助函数以让单个用例清楚呈现输入、动作和结果为准；可保留少量直观重复，不为去重建立复杂的 fixture 继承、通用 DSL 或测试专用框架。
- 涉及并发、重试、取消或恢复时，验证迟到结果、重复操作、部分完成和最终权威状态；不要只断言命令成功或事件已发出。
- 新增自动门禁时，在隔离样例或安全可恢复环境构造目标错误，确认检查确实能阻止它。
- 本地检查不等于 CI 已通过；测试、构建产物、运行实例、远端交付分别核验，只执行任务承诺且获授权的层级。

## 规则变更验证

除链接和格式外，按修改涉及的条款及相邻规则走查正常、边界和不应触发的任务，确认没有误触发、停顿或越权。涉及初始化、权限或 Git 流程时，再覆盖受影响的 `pending` / `ready`、状态缺失 / 非法、中断、模板维护、只读、无上游或已有用户改动场景；初始化完成才切换状态，后续更新不会重复初始化。

上述走查是文本逻辑验证，不能宣称已证明模型在实际会话中必然遵循；若需要行为可靠性证据，用隔离项目执行代表性任务，不污染模板状态。

## UI 验证

本机代理启动游戏默认静音并放在右侧第二块显示器，避免干扰用户主屏工作。2026-09-17 实测该屏是 Godot 索引 **0**（不是 1），物理位置 `(3840,0)`、3840×2160；主屏索引 1。运行/隔离测试入口默认 `--screen 0 --audio-driver Dummy`，录制入口默认 `-Screen 0` 且静音播放。布局变化时先重新枚举，不按 Windows 显示器编号猜 Godot 索引。音乐内容与玩家音量默认值不因代理测试而修改。用户在主屏操作时不为性能测量抢焦点；失焦采样标注无效或后台条件，不当作前台帧率，画面展示可继续用副屏离线录制。

按变化选择：文案检查可理解性和受影响布局；工具交互检查命中、拖动、取消、失焦与错误路径；共享控件、材质或镜头检查受影响场景、窗口尺寸和昼夜可读性。使用真实内容及相关极端场景，编译通过不能替代画面和操作验证。不要求局部改动遍历无关场景与状态。

## Godot 与农场验证

- 入口见 README 与开发准备。修改脚本可用 `--headless --check-only --script <脚本>` 检查语法，但不能把它当成全工程检查；资源与场景改动按需 `--import` 并运行受影响场景。首次克隆或缺少缓存先导入。检查退出码、错误日志与实际产物，未知 CLI 参数可能被静默忽略。
- 纯规则计算优先用可控时间验证；Godot 节点、场景生命周期与输入集成使用实际场景运行或匹配的测试入口，不要求所有改动同时覆盖全部层级。模拟与存档具体判据见 [farm-simulation.md](farm-simulation.md)。
- 场景、Resource 或模型改动检查丢失引用、碰撞 / 射线命中和实际视觉；资产导入成功不能代替玩法或画面验收。
- Windows 构建、窗口与系统集成改动需要相应独立程序验证，不能以编辑器中运行正常替代。未取得目标环境时说明未验证的边界。
- 涉及性能或后台行为时，在可辨识的硬件、分辨率、场景规模和前后台条件下记录 CPU / GPU 帧耗时、内存等相关指标；不能只凭低 FPS 宣称低资源占用。预算按当前阶段确定，不将材料中的参考值当作实测达标。
- 主观体验验证区分作者观察与玩家反馈；画面截图不能证明玩家会因阴影调整布局或愿意次日回访。只有任务包含体验调研时才开展对应活动。

## 关键节点录屏

- 用户要求保留可剪辑的制作过程。只在首个可见成果、资产正式接入、明显交互 / 视觉变化或阶段验收等有展示价值的节点录一条短片；普通回归和反复排错不逐次录制，也不为拍摄延迟必要开发。
- 使用 [录制入口](../scripts/record.ps1)，以 3840×2160 全屏运行，自动展示用 Godot 固定步长逐帧输出，再用 NVIDIA NVENC 编码 H.264 / 60 fps；手动操作保留窗口实时捕获，但当前链路有重复帧风险，必须预览确认。仅显式启动录制时生效，不默认后台录屏；捕获目标必须是本次游戏窗口，不切换为整个桌面或其他程序。无 4K 显示器、硬件编码或窗口捕获能力时明确失败，不静默放大低分辨率或改成软件编码。
- 素材镜头与日常交互分开：录制展示时先稳定停留约 3–5 秒，移动约 1.5–2 秒，再停留 3 秒以上；转动一次只做约 10–20°的小角度、约 3°/秒，避免连续快速切换。收尾保留至少 3 秒。按实际内容适当调整，不改慢普通测试操作，不为拍摄增加产品玩法。
- 视频按编号、时间、中文节点命名，保存到 Git 忽略的 `制作留档/05_开发录屏/`；完整演示通过尺寸、编码、帧率、逐帧时间戳和运动连续性检查后加入索引；手动 / 提前停止片段标明待人工复核。索引附展示内容、代码基线、实际工具贡献和剪辑提示；失败 / 中断文件保留诊断，不当成成功素材。文字归因用于后期剪辑，不自动把工具广告叠在游戏界面中。
- 录屏的 60 fps 是成片时间轴，不是游戏性能通过的证明；不能把自动演示说成用户实测。自动演示的固定步长输出明确标为离线演示渲染；实测性能独立验证。运动区间要检查相邻画面有无异常重复 / 跳变并预览，不能用 FPS 标签、时间戳或静态截图替代；静止停留不应被误判为掉帧。采样区间随镜头脚本更新。

## 开发服务

本项目尚无长期开发服务。用户要求每次改完后启动最新游戏供其观察：完成改动及必要验证后，通过 `scripts/godot.ps1 -Action Run` 或既有隔离运行入口启动可交互游戏，默认静音、右侧第二屏，确认窗口就绪并保持运行，不在收尾时关闭。已有实例确认对应最新内容时可直接保留，避免重复开窗；需替换时只处理本任务明确归属的旧预览，保留用户已有实例和未保存场景，不按进程名批量关闭或擅自重启编辑器。交付运行结果时分别报告编译、测试、构建和实际运行证据。

上述交付预览也适用于规则或文档改动；纯只读咨询无需启动，用户明确要求不启动时遵循当次要求。启动失败应报告实际原因，不能以进程创建成功替代窗口就绪。涉及真实数据、费用或额外权限时按既有授权边界处理。未来新增长期开发服务时，再按实际入口补充归属识别、就绪、重启和安全停止约定。

最终回复结尾按实际情况选一条：

- `🟢 游戏已启动（静音，第二屏）`
- `🟢 开发服务已启动`
- `🔄 开发服务已重启`
- `✔️无需重启（开发服务保持运行）`
- `⏭️无需启动（本次改动不影响开发服务）`
- `🔴 开发服务启动失败：<原因>`

## 交付

只报告实际执行的验证及结果。无法验证时说明具体原因、替代证据与剩余步骤，不伪造通过，也不为无关检查未执行而道歉。确认本任务差异、规则同步、必要的迁移 / 生成 / 重启均已处理；Git 提交和同步结果单独按 Git 规则报告。
