# 江南树木：桂花动态资产与制作流程

2026-09-17，用户要求重生成多种九月江南树木，并补充枝条摆动和落叶需求。本目录保留一棵桂花的完整生成、语义分割、自动绑定兼容性实测及后续动态接入；**当前已替换左前方一棵树并实现风动与落叶**，其他树种待后续制作。原树来源仍在相邻 `Tree/`，不覆盖历史。

3. 独立语义分割 `v2.0-20260430`，balanced、split_by_connectivity=false；任务 `621b897b-e258-44fd-b74b-59d86fd834e8`，40积分。[分件原模](20260917/osmanthus/segmented/model.glb)和[任务回显](20260917/osmanthus/segmented/task.json)保留。
4. 免费自动绑定检查针对未分割整树；任务 `b197026e-0dac-483e-a665-4b47b1f96fa9`，0积分。实际返回 **riggable=false、rig_type=others**，见[响应原件](20260917/osmanthus/rig-check.json)。未调用付费绑定/重定向，没有Tripo生成的骨骼或动作；游戏风动由本地制作。
5. Blender 5.2.2 LTS正反侧渲染及拓扑检查；研究用着色检查源在[segmentation-inspection.blend](20260917/osmanthus/segmentation-inspection.blend)，彩色只区分服务返回部件，不是最终材质，也不是自动识别的树种/部位名称。后续游戏接入见下节，不覆盖研究原件。

合计100积分，账户变化已核验，冻结状态未公开。原图/原始GLB不被检查工具修改；归档任务去掉临时上传对象位置，不保存签名地址或凭据。

## 观察与制作取舍

| 项目 | 整树 | 分割后 |

| 纹理 | 单张4096² | 19张128²～512²，UV已重排 |
| 骨骼/动作 | 0 / 0 | 0 / 0 |
| 开边（审计副本焊合UV接缝） | 0 | 合计1514 |
| 坐标 | 原始范围 | 最大跨度归一化到1、部件各自局部原点 |

恢复统一尺度和中心后，分件顶点到原网格最大距离约6.14e-8。可以用分件结果标记原模型区域，保留原4K材质。不能直接按19个部件局部原点旋转：分割切过树枝，静止组装完整不证明摆动时无缝。着色图还显示枝叶混合分组，没有逐叶语义保证。

原始桂花冠幅偏扁（厚度/宽度约0.36），叶片比例偏大；运行版保留卡通大叶并增加50%冠深，原参考和原件不修改，仍待用户主观确认。后续树种参考应提高冠深、补一致侧视或整理叶簇，不直接用骨骼弥补原始造型问题。

流程和官方资料统一见 [Tripo工作流](../../../docs/tripo-workflow.md#树木分件与动画已验证边界和后续制作方案)：整树参考与模型 → 必要分件 → 保留原几何/材质、制作连续权重或少量枝条骨骼 → 叶簇轻颤 → 独立稀疏落叶 → 高低档、真实场景及运动接缝检查。桂花未通过Tripo自动绑定，本轮在Blender制作连续权重，不把动物动作预设用于自然风吹树枝。

## 当前游戏接入

- 位置：左前岸边、入口藤架靠玩家一端，`Environment/WestTree`，坐标 `(-6.05,0.13,4.3)`、偏航15°。保留其余旧树；挪开一块岸石，树根避开藤架、竹篱和地面装饰槽。
- 重建：Blender 5.2.2 `--background --python-exit-code 1 --python ArtSource/Environment/Trees/20260917/prepare.py`。输出[可编辑源](20260917/osmanthus/osmanthus.blend)、[审计](20260917/osmanthus/asset-audit.json)与 `Game/art/environment/osmanthus/` 两档。原始38798三角全部保留在高档；低档22114三角来自同源，单材质／4K原贴图。两档导入关闭额外自动LOD，普通游戏当前用高档。
- 人工低档先在工作副本合并几何接缝再减面，面角UV保留；两档独立重导入后均0开边／0过度连接边。早期直接减导入拆点的低档出现9342条开边，已修复且新增高低档闭合性回归；不使用该失败版。
- 分件只辅助源文件中的 `TripoPart_00..18` 分组；19张降分辨率纹理和切口未替换原模型。连续顶点色R控制枝干弯曲、G控制叶片轻颤、B控制相位，重合接缝统一权重；底部20%锁定，避免独立部件旋转露缝。没有骨骼和动作轨道，游戏由 `plant_wind.gdshader` 执行变形。
- 落叶：`falling_leaves.gd` 取真实树冠中的清空区域发射，六个共享网格实例循环，8秒飘落、3秒停留、2秒缩小消退；叶片是本地制作的小网格，不是另一次Tripo生成。根附近草地落点有界，不引入每叶刚体或无限累计。更换树形／位置必须重新校验发射区，不照抄坐标。
- 检查：`osmanthus_debug_scene_test.gd` 检查动画实例、落点、自由视角和全场景正LOD偏置；`osmanthus_clearance_test.gd` 在60秒13个风相位对25处附近真实网格边界检查，未发现树木穿过静态邻居；`lotus_stone_clearance_test.gd` 重查挪石后的41份荷花网格／146块岸石。样本通过不替代后续新摆件和新动画范围验收。
- 本轮不新增Tripo费用，累计生成与分件100积分；其他树种尚未制作。额外自动LOD曾把本树叶缘削成尖片，全局零偏置根因与处理固定在[资产流程](../../../docs/asset-workflow.md#lod-与破面验收)。

已做树种方向研究：桂花、垂柳、黄山栾树、乌桕，九月中旬以绿色为主。早银桂始花具有品种/温度差异，不能假定当年满树盛放；乌桕避免深秋全红。物候参考：[杭州早桂记录](https://www.hzzx.gov.cn/cshz/content/2024-09/02/content_8781833.htm)、[临海黄山栾树记录](https://lhnews.zjol.com.cn/lhnews/system/2023/09/22/034361211.shtml)、[上海古猗园乌桕记录](https://lhsr.sh.gov.cn/shhx/20201105/d5cd59fc0b544c60be8a2275b2af681b.html)。这些是选型依据，不代表2026年9月17日实际天气或已生成四种树。

### LOD 修复对比的证据与限制

- [修复前失败低档审计](../../../制作留档/03_处理与验证/20260917_桂花动态与LOD根因修复/失败低档审计_修复前.json) 保存了 `osmanthus_low.glb` 的9342条开边；当时审计还未加入闭合高低档回归，所以报告中的空 `failures` 不代表该低档合格。此入口保留的是数值证据，**不是修复前模型或同机位前后视频**。
- [修复后全库 LOD 数据](../../../制作留档/03_处理与验证/20260917_桂花动态与LOD根因修复/mesh-lod-repaired/mesh-lod.json) 包含基础／最低档拓扑以及 `draw_bias_zero` 等对照绘制量；同目录图片是修复后近景，不冒充已经完成的前后对照图组。
- 若需要“强制最简档→正常选档”的视频，用基线资产在隔离场景固定相机、光照、分辨率和动作相位，仅切换对应 LOD 条件。若重现人工减面破缝，需从原模副本执行当时错误流程、核验现象后标记“问题重现”；不得覆盖现役模型或将补拍说成历史录像。

补拍按实际需要制作独立片段并保留干净画面；原模转台、分件着色／展开、权重和最终动态分别标明工具贡献。参考由图片工具生成，Tripo提供整树／纹理及分件，Blender负责整理和权重，Godot负责运行风动与落叶。19件分割存在切口、贴图重排；最终方案保留原4K材质并使用连续权重，不能剪成“Tripo自动分件后直接骨骼动画成功”。
