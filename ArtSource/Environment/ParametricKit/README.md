## 无孔木栏杆与统一木材（2026-09-25）

用户指出两个问题：横杆／斜撑与立柱质感不同，以及固定榫孔被随机转向后与实际接头不对应。原因是混用了两套纹理，且首轮生成规则没有把原木柱的孔位作为连接约束。本次采用用户允许的“全部无孔”方案，制作封闭八边倒角方木桩、柱帽和绳圈；保留轻微磨边，横杆和斜撑共用相同木纹、粗糙度及反光设置，纤维沿各自长度方向。

- `railing_modules.blend` 是可编辑源，`prepare_railing.py` 为重建入口，`railing-audit.json` 保存实际导出结果。木桩高／低740／116三角形，横杆108三角形；基准桩高0.9米、柱帽0.205米宽、杆截面0.085米。原图不变，只通过UV选择 `[.709,.462]–[.855,.580]` 的木纹区域，细杆与木桩保持接近的横向纹理密度。三份GLB均链接同一原颜色图，无新增运行贴图或付费生成。
- 立柱依据路径方向放置；种子只允许对称实木桩作半周翻转，改变纹理／磨边朝向。上下横杆和斜撑的实际端帽收进柱体，斜撑位于上下杆之间，不再向侧面偏移后硬穿接头。转角共用一根实木桩，不模拟隐藏榫卯的加工细节。
- Blender合并部件前统一UV层名为 `WoodGrain`；否则柱帽原 `UVMap` 与柱身的新UV层并存，导出主UV时柱帽可能退回零坐标而变成纯色。重导入检查每个木材面的UV都位于选定区域，另检查有限坐标、三角数、零开边以及四侧16条射线命中旧榫孔高度的实体外壁。人工低档关闭额外自动LOD。
- 专项 `tests/component_railing_joint_test.gd` 检查实际运行材质共享，直线／转角／折线各自默认、最小、最大尺寸与正负坡度下的横杆／斜撑端部确实进入实体柱。画面覆盖默认、正反近景、三形态、最大／最小坡地和远近返回；沿用 `component_lab_scene_test.gd` 验证接地、种子、按钮与复制。

```powershell
blender --background --python-exit-code 1 --python ArtSource/Environment/ParametricKit/prepare_railing.py
& scripts/godot.ps1 -Action Import
& scripts/godot.ps1 -Action Run -ExtraArgs '--script','../tests/component_railing_joint_test.gd'
```

重建只覆盖本目录的 `railing_modules.blend`、`railing-audit.json` 和运行目录三份 `fence_*.glb`，不覆盖旧桥源。截图在 `.local/verification/solid-railing/`，用户标注原图与最终证据归档到 `制作留档/03_处理与验证/20260925_木栏杆材质与连接/`。参考来源是既有Tripo木柱纹理和用户反馈，未新增参考图生成；建模由Blender完成，Godot只拼装，未将新柱几何记成Tripo输出。节点基线为 `79223037`；已有截图与源，未另录过程视频。旧2026-09-24组合性能记录属于修改前版本，本次没有重测或声称资源收益。

## 桂花组件与验证（2026-09-24）

采用连续的 Tripo 树干分叉与可复用枝叶簇。早期“原桂花截根＋程序圆管枝干”在实景显得生硬，并出现粗切口，不采用；研究室已经移除圆管枝干代码。新的框架由参考图单独生成，主干和分叉保持同一连通表面。程序在连续框架上做有界扭转、展冠与偏冠，枝头位置同步变换，再用种子决定叶簇大小、朝向及同一芽点的附加枝叶。它能产生轮廓与疏密变化，但不是任意拓扑、任意树种生成器。

- 枝叶簇：任务 `67c5df09-8c45-404e-9689-5125cd47da95`，120积分，原始4131三角形；树干框架：任务 `4ff9958f-7347-47ba-aa4e-d79f4d008d27`，120积分，请求12000、实际12403三角形。两件合计240积分，均为 P2-20260801＋v3.5-20260815 detailed、无PBR、delight=false。精确输入及采用状态分别见两个 generation-record JSON。图片工具未返回型号或费用，不补造。
- `prepare_tree.py` 保留两件原模，在副本中校正轴向、尺寸与枝叶真实切口。框架原有97条开边，通过23个局部补面修复；高档12454／低档6226三角，干净重导入后均零开边。枝叶高／低4131／2064三角，保留薄叶的开放边界，不将它们声明为封闭实体。
- 以树根出发的网格路径寻找29个枝头，记录位置、轴向与半径。叶簇底部0.22米渐细、埋入枝头0.085米，避免粗锯口露在外面；低于0.18米的枝叶权重固定，末端逐渐参与风动。原件的轴向不能用最低顶点猜测，本批叶簇切口实际朝原模+X。
- 可编辑源 `tree_modules.blend` 打包纹理；`tree-audit.json` 记录尺寸、边界、三角数、源与导出复核；`tree_sockets.json` 是运行连接数据。高低档各自引用共同的 `tree_trunk_color.jpg`／`tree_cluster_color.jpg`，重复叶簇通过 MultiMesh 共享网格；每棵独有的连续树干变形生成独立网格。26米附近切换人工档，关闭这四份导入物的额外自动LOD。
- `tree_kit.gd`：树高3–5.8米、冠幅2.8–6米、疏密0–1、偏冠0–0.7。尺寸由实际顶点求界后匹配参数；高窄、低圆、偏冠三个预设可并排检查。叶色使用与主岛桂花相同的风动材质处理。

## 组合、主岛对照与资源边界（2026-09-24）

`tests/component_collection_test.gd` 在同一光照里放置一组木栏杆、一组竹架、一棵桂花和一座民居，并验证重复构建共享静态网格。主岛栏杆调用现役 `fence_geometry.gd`，主岛竹架读取现役 `climbing_trellis.glb` 并应用实际院落材质；只建立参考节点，不启动主游戏或读取农场存档。木栏杆与原竹栏是材质／比例对照，不宣称它们是同一种结构。

首次组合截图发现26米附近树冠、屋脊被湖面覆盖：Godot的 Self 可见距离淡化会临时进入透明管线，与写深度水面出现排序问题；3D标签也需要透明裁切。官方说明见 [Visibility ranges](https://docs.godotengine.org/en/stable/tutorials/3d/visibility_ranges.html#fade-mode)。本实验改用不透明即时切换，统一每个物件的近远包围盒，并将切换余量设为0；本机0.5米余量在首次进入临界区时仍出现两档均不显示。保留人工低档，代价是切换时存在小幅细节跳变。组合测试补拍24／25／26／27米及返回，并比较树开启／隐藏后的实际像素，防止把全树消失当成测试通过。

最终代表组合（RTX4090、Godot4.7.2、D3D12 Forward+、1600×1000、120/120前台帧）：生成含参数规划及首次载入约901ms，缓存后四类规划与构建约177ms；CPU渲染中位0.476ms、GPU2.037ms，工作集535.4MiB，引擎video分配695.9MiB，161次绘制调用。远景样本采集时窗口失焦（0/120前台帧），保留原始数据但不用于前台性能或收益比较；远景画面与切换检查仍有效。首生成不等于清空操作系统缓存后的冷启动。这些数字包含湖面、界面和加载的资产，没有旧背景岛同条件基线，不给出替换节省比例。
