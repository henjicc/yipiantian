## 栏杆画笔（2026-09-25）

独立研究室的「画栏杆」进入14×14米地面画布，左键按住绘制，拖动中预览实际构件。首次自绘替换示范预设，后续笔画追加到已有结果，靠近开放端点0.45米以内会吸附：可延长单端、连接两段、或连接同一路径的两端重新闭合。新笔画距自身起点0.45米以内且长度超过2米时自动闭合，接缝共用一根立柱；「结束画线」恢复左键旋转，「恢复预设」清除当前编辑及撤销历史并返回原组合。右键／中键平移、滚轮缩放沿用现有交互。Esc在笔画中取消当次修改，空闲工具中退出工具，普通观察时保留退出程序行为。

`railing_brush.gd` 负责鼠标到实际坡面的投影、采样及预览，`railing_path.gd` 负责去抖与路径拟合，`railing_edit.gd` 负责多段路径裁切、端点合并和交叉检查，`railing_kit.gd` 沿结果布柱搭杆。RDP简化容差0.12米，合并不足0.28米的残余边；保留明显转角，按最大开间细分，曲线由短直木段贴合。复制参数中的 `paths` 保存编辑后的地面折线及闭合标志，改种子／栏高／开间／坡度不会丢失多个片段；自绘时隐藏预设长度和走向，停用三预设对比。

「擦除」以0.35米半径裁掉经过的部分，连续拖动对相邻采样之间补采，避免快速划过漏擦。剩余过短的端头会一并清理，避免堆叠立柱；闭环被擦开时保留正确的开放端点。拖动先预览、松手提交，取消保留原结果。「撤销」或工具中的Ctrl+Z恢复上一步，最多20步；全部擦空保留空画布，继续绘制不会自动恢复示范预设。绘制和擦除均有贴合坡面的悬停圆环，沿用地形编辑的绿／橙配色，吸附端点变浅金；绘制环半径0.22米，擦除环等于实际裁切半径。圆环不参与阴影、不被栏杆遮挡，移至面板／水面或失焦时隐藏。

支持多条独立路径／闭环、研究室平面或统一坡面。过短、急回折、交叉或非邻接边间距不足0.22米的路径拒绝生成并保留上次结果；不自动创建T形或十字节点。单笔最多1024个采样点，全部栏杆总长上限80米；越过地面、进入面板、失焦或改变窗口尺寸取消未完成笔画。模型预览最多每100毫秒更新一次，空闲工具仅更新圆环投影，退出工具停止逐帧处理；保留共享MultiMesh、旧材质与关闭凹凸状态，没有新贴图、付费模型或主游戏存档接入，不据此宣称整游戏性能收益。

验证入口：`scripts/godot.ps1 -Action Run -ExtraArgs '--script','../tests/railing_drawing_test.gd'`；4K加 `--screen 0 --fullscreen` 及用户参数 `--drawing-review-4k`。专项覆盖抖动直线、S形、闭合、角点、实际杆端插入实木柱、开间／拟合误差、确定性、鼠标预览与提交、Esc／失焦／面板／地面边界取消、坡面绘制、复制及切换构件后保留路径。1600×1000与4K专项通过，原实木材质／接头专项另作回归。屏幕缩放下自动输入必须以 `push_input(event,true)` 注入视口坐标，否则相机投影得到的位置会再次缩放；正式鼠标事件由引擎正常转换。

## 无孔木栏杆与统一木材（2026-09-25）

用户指出两个问题：横杆／斜撑与立柱质感不同，以及固定榫孔被随机转向后与实际接头不对应。原因是混用了两套纹理，且首轮生成规则没有把原木柱的孔位作为连接约束。本次采用用户允许的“全部无孔”方案，制作封闭八边倒角方木桩、柱帽和绳圈；保留轻微磨边，横杆和斜撑共用相同木纹、粗糙度及反光设置，纤维沿各自长度方向。

- `railing_modules.blend` 是可编辑源，`prepare_railing.py` 为重建入口，`railing-audit.json` 保存实际导出结果。木桩高／低740／116三角形，横杆108三角形；基准桩高0.9米、柱帽0.205米宽、杆截面0.085米。原图不变，只通过UV选择 `[.709,.462]–[.855,.580]` 的木纹区域，细杆与木桩保持接近的横向纹理密度。三份GLB均链接同一原颜色图；后续表面凹凸补充见下节。
- 立柱依据路径方向放置；种子只允许对称实木桩作半周翻转，改变纹理／磨边朝向。上下横杆和斜撑的实际端帽收进柱体，斜撑位于上下杆之间，不再向侧面偏移后硬穿接头。转角共用一根实木桩，不模拟隐藏榫卯的加工细节。
- Blender合并部件前统一UV层名为 `WoodGrain`；否则柱帽原 `UVMap` 与柱身的新UV层并存，导出主UV时柱帽可能退回零坐标而变成纯色。重导入检查每个木材面的UV都位于选定区域，另检查有限坐标、三角数、零开边以及四侧16条射线命中旧榫孔高度的实体外壁。人工低档关闭额外自动LOD。
- 专项 `tests/component_railing_joint_test.gd` 检查实际运行材质共享，直线／转角／折线各自默认、最小、最大尺寸与正负坡度下的横杆／斜撑端部确实进入实体柱。画面覆盖默认、正反近景、三形态、最大／最小坡地和远近返回；沿用 `component_lab_scene_test.gd` 验证接地、种子、按钮与复制。

## 木纹表面凹凸（2026-09-25）

**以下为已停用的历史研究，当前方案以上节为准；复现需使用提交 `e2d26410` 的生成器、源与测试。** 用户反馈无孔版仍像平面贴色，随后指出首版法线颗粒过强。历史版本的 `prepare_railing.py` 调用 `bake_railing_relief.py`，在Blender 5.2.2 LTS Cycles中对木纹高度做九点加权预滤波，保留宽浅起伏，再烘焙切线空间法线与粗糙度；已移除首版额外叠加的细纤维噪声。预滤波仅发生在离线烘焙中，没有增加运行时九次采样。原颜色图、UV区域、连接和模型轮廓不变；这是假定木纹沟槽的材质塑形，不是从颜色图恢复出的真实扫描几何。

- 共享 `fence_wood_normal.png`（1024²，OpenGL +Y）及 `fence_wood_orm.png`（512²，G粗糙度、B金属度零）。法线强度0.65，粗糙度范围0.88–0.96；三个构件及远近档引用同一份图片，没有逐根复制材质图。两图压缩像素数据含mipmaps共1,572,904字节，约1.5MiB，原2048²／1024²版约6MiB；这不是整个进程／驱动显存测量。没有新增Tripo／图片生成调用或付费，法线由Blender材质烘焙产生。
- 历史提交的 `railing_modules.blend` 保留 `WeatheredTimberReliefSource` 材质节点和打包图片。编辑源保持多边形；仅导出时三角化，确保八边端面的切线可计算，GLB审计检查实际导出了 `TANGENT` 和法线／粗糙度引用。三角数仍为740／116／108。

## 桂花组件与验证（2026-09-24）

采用连续的 Tripo 树干分叉与可复用枝叶簇。早期“原桂花截根＋程序圆管枝干”在实景显得生硬，并出现粗切口，不采用；研究室已经移除圆管枝干代码。新的框架由参考图单独生成，主干和分叉保持同一连通表面。程序在连续框架上做有界扭转、展冠与偏冠，枝头位置同步变换，再用种子决定叶簇大小、朝向及同一芽点的附加枝叶。它能产生轮廓与疏密变化，但不是任意拓扑、任意树种生成器。

- 枝叶簇：任务 `67c5df09-8c45-404e-9689-5125cd47da95`，120积分，原始4131三角形；树干框架：任务 `4ff9958f-7347-47ba-aa4e-d79f4d008d27`，120积分，请求12000、实际12403三角形。两件合计240积分，均为 P2-20260801＋v3.5-20260815 detailed、无PBR、delight=false。精确输入及采用状态分别见两个 generation-record JSON。图片工具未返回型号或费用，不补造。

- 以树根出发的网格路径寻找29个枝头，记录位置、轴向与半径。叶簇底部0.22米渐细、埋入枝头0.085米，避免粗锯口露在外面；低于0.18米的枝叶权重固定，末端逐渐参与风动。原件的轴向不能用最低顶点猜测，本批叶簇切口实际朝原模+X。

## 组合、主岛对照与资源边界（2026-09-24）

`tests/component_collection_test.gd` 在同一光照里放置一组木栏杆、一组竹架、一棵桂花和一座民居，并验证重复构建共享静态网格。主岛栏杆调用现役 `fence_geometry.gd`，主岛竹架读取现役 `climbing_trellis.glb` 并应用实际院落材质；只建立参考节点，不启动主游戏或读取农场存档。木栏杆与原竹栏是材质／比例对照，不宣称它们是同一种结构。

首次组合截图发现26米附近树冠、屋脊被湖面覆盖：Godot的 Self 可见距离淡化会临时进入透明管线，与写深度水面出现排序问题；3D标签也需要透明裁切。官方说明见 [Visibility ranges](https://docs.godotengine.org/en/stable/tutorials/3d/visibility_ranges.html#fade-mode)。本实验改用不透明即时切换，统一每个物件的近远包围盒，并将切换余量设为0；本机0.5米余量在首次进入临界区时仍出现两档均不显示。保留人工低档，代价是切换时存在小幅细节跳变。组合测试补拍24／25／26／27米及返回，并比较树开启／隐藏后的实际像素，防止把全树消失当成测试通过。

最终代表组合（RTX4090、Godot4.7.2、D3D12 Forward+、1600×1000、120/120前台帧）：生成含参数规划及首次载入约901ms，缓存后四类规划与构建约177ms；CPU渲染中位0.476ms、GPU2.037ms，工作集535.4MiB，引擎video分配695.9MiB，161次绘制调用。远景样本采集时窗口失焦（0/120前台帧），保留原始数据但不用于前台性能或收益比较；远景画面与切换检查仍有效。首生成不等于清空操作系统缓存后的冷启动。这些数字包含湖面、界面和加载的资产，没有旧背景岛同条件基线，不给出替换节省比例。
