- [x] **02｜定义动物活动区域与行为配置。** 分清可游水域、可走草地/道路、安全边距、禁入区、休息点与兴趣点。每种动物有速度、转向、停留、结伴倾向，每只动物有独立节奏。开始时适配当前场景，数据与具体坐标分离，供第08项布局系统接管。完成标志：动物与障碍使用清楚的空间边界，不靠到处散落的固定坐标控制。
- [x] **03｜鸭鹅扩大范围并自由游动。** 使用主岛左侧与前方连通水域，随机选择可达目的地，避免不断回到最近旧点；时而游动、停留、探水、理羽和结伴，鸭鹅有不同节奏。完成标志：有明显跨区域位移、不再固定绕椭圆、不齐步运动、速度与转弯自然。
- [x] **04｜鸡在主岛自然移动。** 连通前岸小路、屋侧空地和可走草地；随机走走停停、啄食、观察、理羽，绕开田地、建筑、桥边危险处和摆件。完成标志：鸡能在完整允许范围内换位置，不原地滑行或卡在角落，也不践踏作物。
- [x] **05｜完成与位移一致的动物动画。** 鸡有独立行走、站立、啄食动作；左右脚交替抬脚前迈，支撑脚贴地，步频与实际速度一致，停步和转身平滑。鸭鹅划脚、身体浮动、朝向和尾波响应实际运动。完成标志：近景与低机位看不到明显滑步、双脚同步摆动、倒着游或尾波跑到前面；必要时在既有骨架上修权重、脚部锁定及贴地。
- [x] **06｜完成避障、让行与卡住恢复。** 检查整条移动路线和身体宽度，避开岸石、船、系船绳、荷叶及同伴；互相靠近时让行，目标不可达时重新规划。完成标志：允许区内随机运动不穿模、不上岸、不掉水；恢复不瞬移、不每帧改目标抖动，停留动作不会无限卡死。
- [x] **07｜完成动物整体验收并留存版本。** 覆盖全部动物、全活动范围、路径边界、常见互相阻挡、昼夜、近景和副屏失焦；检查运行开销。保持当前7只的范围，动物数量不随时间无限增长。完成标志：移动、动作和环境融为完整体验，保存可运行版本与必要对照素材；无需要重生成时不重复付费。

## 第二阶段：让小院布局支持完整玩法

参数化值得做，但要把“数据改变后整个院子还能合理衔接”当作目标。主要参数由开发配置管理；玩家只接触易理解的整理、布置和扩建，不直接操作密集工程参数。

**执行状态（2026-09-18）：第08项进行中。** `Game/layout/courtyard_plan.gd` 已成为主要落点的共享数据源，主场景在子节点建场前将同一实例交给院落、农田与生活摆件；岸石／草地轮廓、路径、围栏、建筑／泊位、装饰槽、田块位置与朝向、动物区域／休息点已接入。默认构图保持；移动旋转田块的选格与作物身份检查111项通过，真实主场景共享布局与动物接触检查通过。岛岸本体已由共享轮廓生成，平地同步约束短草与鸡的活动边界；默认场景田角和桥头支承、扩大与不规则岸形闭合检查通过，源和近景见[岸坡记录](../../ArtSource/Environment/Banks/README.md#布局参数化节点--20260918)。受控扩岸已接入岸树、竹花、荷花、岸石、泊位、动物区域、全景／布置镜头和雾清晰区，并修复落花固定旧坐标；默认与扩展实景检查通过。任意桥头迁移、围栏／道路自动重排和完整高度联动尚待接入；田数／行列／尺寸／朝向与稳定格ID已接入土面、高亮、碰撞、种植、鸡禁入和聚焦景深；布局与作物进入v5存档，在真实七田、5×3／3×4、旋转与新增列上通过播种、接缝、重进和备份恢复检查。占用格删除会整体拒绝，不丢失作物；数据最多12田／384格，尚未作为性能上限验收。玩家编辑、空间冲突提示、道路围栏自适应和撤销未完成，不能把底层能力当成可扩建玩法。

- [ ] **08｜建立统一的小院布局数据。** 集中定义岛岸轮廓、地面高度、田块、道路、建筑锚点、桥头、围栏、装饰区与动物区域。设置稳定身份，视觉与状态从布局派生。完成标志：田、路、栏杆和动物不再各自维护一套互相冲突的位置；重建不会丢失已有布局内容。
- [ ] **09｜参数化岛岸、土地面积与接地。** 支持受控的轮廓、面积、岸坡宽度和高度配置，生成圆滑可用的地面，岸石和水草适应水线；桥两端、船泊位始终有合理支承与空间。完成标志：至少对当前布局、扩展布局和不规则布局检查，均无悬空、断岸或裸露生硬侧面；改变土地不是整体拉伸房屋和树木。
- [ ] **10｜参数化田块与种植数据。** 支持田的数量、尺寸、行列、间距和朝向，同步生成土面、碎土、培土、压边石、碰撞与鼠标选格。独立随机种子避免重复排列。完成标志：移动田块不改变作物身份；调整面积先处理已种作物和占用冲突，不能静默丢失；不同布局能正常播种、浇水、收获、保存恢复。
- [ ] **11｜自动衔接道路、围栏与出入口。** 围栏沿指定边界生成并正确转角，门口、屋门、桥头与动物通路保留开口；道路连接重要落点、绕开田地。完成标志：新增/移动田地后不必逐根手摆围栏，路不穿田、不堵门，栏杆不会压到桥和家具；保留少量有意的美术调整点。
- [ ] **12｜联动摆件、植被、动物与镜头。** 布置点关联真实支承面，植物随岸边/院落区域排布并避让，动物活动区和路径随有效布局更新；相机全景、聚焦、景深清晰区、环绕雾的主岛边界、接触阴影与水岸遮罩同步适配。完成标志：扩建后没有“地变大了但雾、鼠标、动物和阴影还停在原地”的问题；邻居岛继续保持统一世界尺度。
- [ ] **13｜完成可用的院落整理与扩建操作。** 提供有限但完整的布局选择、田块整理、围栏样式和区域扩展；预览占用、确认修改、取消恢复，支持撤销最近一次布局调整。移动/缩减有作物的田地必须明确保留或转移方式，不把农作物直接删除。完成标志：玩家能把小院改成自己的布局，保存重进一致，操作简单且不需要理解参数表；不扩展为任意地形雕刻器。

## 第三阶段：完整低压力玩法

故事基调：照料一方临水小院，把收成分享给周围人家，逐渐认识这片湖。没有债务、危机或必须拯救全村的重担。已有十二种菜都应有用途，不只围绕青菜和白萝卜刷数字。

- [ ] **14｜完善收获用途、食材存量与目标。** 把累计收获成就和可使用食材分开；支持食材分类替代、清楚的收获/使用反馈，重新协调十二种菜与现有装饰解锁。完成标志：送菜和烹饪不会倒扣累计成绩，种不同菜有各自用途，少种几格也能体验主要内容。
- [ ] **15｜完成邻里菜篮与回礼。** 建立多户邻居身份、喜好和常驻小愿望，支持挑选、送菜、交付表现、回礼选择和领取；愿望不设截止，可接受同类菜。完成标志：多户、多轮流程可持续体验，有去有回；不重复扣食材/发奖励，离线不丢失信件与回礼，不只实现一笔示范任务。
- [ ] **16｜完成邻里故事与场景变化。** 为各户安排有起承转合的日常故事，与分享、种植和院落摆件相联系；用小笺、短对话和对方屋前变化讲述。完成标志：至少三户各有完整故事线和完成后的日常往来，不是人物永远重复一句话；错过现场表演可回看或再次触发，不靠现实时间卡进度。
- [ ] **17｜完成厨房、晾晒与食记。** 利用新厢房、桌面、晒架和陶罐，制作清炒、汤食、腌渍、晾晒等连贯操作与成品表现；配方覆盖不同现有作物。完成标志：选材、制作、展示、食记和分享全部衔接，配方可预览、有同类替代；无烧糊惩罚、食物腐烂或必须守时收取。
- [ ] **18｜让布置产生生活回应。** 长凳、花盆、灯笼、晒架、休息点等引出动物停留、可见食材、夜间茶具等变化；允许移动、替换及保存。完成标志：多种摆法都有合理回应，物件位置改变后动物仍能到达，未摆某件东西不降低生产效率、不形成唯一最优布局。
- [ ] **19｜完成动物亲近互动。** 支持命名、可选投喂、休息点偏好和互动反馈，让动物逐渐表现出不同习惯；与自然游走共用行为逻辑。完成标志：点击互动、靠近、回应、返回日常活动完整，不堵农事输入；不喂也正常生活，不加入饥饿死亡、每日清洁或强制繁殖产出。
- [ ] **20｜完成田园见闻与相册。** 记录首次收成、邻里片段、动物结伴、晨昏与院落变化；支持查看、拍照、保存和回顾。完成标志：条目有内容、有画面，重要见闻不用守着屏幕抢拍，未发现内容不靠红点和完成率催促收集。
- [ ] **21｜完成时令小景和轻量整理。** 以江南九月为默认，提供可主动选择且可重复体验的秋日晾晒、雨后院落等主题；需要扩展季节时先核验植物与农作物。开荒/除草作为一次性整理或自主美化，工具可完成从荒地到可用地的过程。完成标志：主题涉及相应视觉、声音、可见生活变化；不持续长草强迫清理，不设错过现实日期就绝版的内容，不以天气毁坏收成。
- [ ] **22｜完成湖面慢游与邻居拜访。** 使用现有船和可见邻居岛，完成上船/进入观赏、平滑移动、靠岸查看、往来互动和返回；远近资产按观察距离准备。完成标志：船不穿岛与水草，靠近岛屿有足够完整细节，拜访与邻里玩法连通；无需燃料、体力、限时路线或额外大世界。
- [ ] **23｜整合工具、信息与首次体验。** 播种、浇水、收获及整理工具保持同一套上图下字、持物鼠标、悬停预览与取消逻辑；新内容通过场景入口和主动展开界面承载。完成标志：没有常驻任务墙、提示轰炸或互相争抢输入；首次进入能较快体验一个完整生活变化，回访可以自选种田、布置、交往或纯观赏。
- [ ] **24｜完成低压力成长与存档闭环。** 检查种植→收获→分享/制作→回礼/关系→布置/新见闻之间的节奏，处理重复领取、保存退出、离线回访和布局状态一致性。完成标志：不签到、不催收、不掉好感、不腐烂；长期离开仍能接着玩，主要内容不要求种满96格或重复刷唯一作物。早期开发不要求兼容旧数据，也不擅自删除旧文件；前置留存包用于保持旧版可运行。

## 简单注意事项

1. **资产按需留存。** 新生成或显著修改的资产保留采用参考图、原模型、必要拆件/骨架、可编辑源、导出物和参数/费用；现有合格资产优先复用。关键来源只留一份并建索引，别反复拷贝大文件。涉及Tripo继续先统一风格参考图，再生成模型，遵循项目级资产skill。
2. **录屏只在很有必要时做。** 用户明确要片、不可复现的关键过程，或必须用动态对照才能说明重大变化时才录一段。不常驻录屏，不每次修改/验证都录；能从保存源文件重现的内容先记节点和少量截图，需要视频时再集中补拍。
3. **先后依赖要守住。** 02–07先交付动物完整行为；08–13完成能支持变化的小院；14–24依次接上完整玩法，最后25整体交付。参数化阶段要把已完成动物重新接入布局数据，不能保留两套冲突边界。各阶段结束保持可运行；不要为了做完整而跳过衔接、保存和退出流程。
4. **低压力与清爽画面不变。** 新系统提供选择和回应，不变成必须完成的每日作业；UI延续已有规范，不随手增加提示。
