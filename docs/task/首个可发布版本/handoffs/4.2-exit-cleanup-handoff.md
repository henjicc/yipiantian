# 4.2 补修交接：正常退出的音频清理

- 日期：2026-09-17。
- 范围：普通产品关闭生命周期；不改变声音素材、播放过程、音量设置、农场规则或保存格式。016 影片先于此补修，画面与播放过程未变，不重录。
- 状态：代码、45 项自动回归和普通发行包三路实际退出验证通过；本人运行全部退出，GPU 已归还主代理协调后续测试。

## 问题与证据

4.2 的普通发行包在两次关闭中留下 `12 ObjectDB instances` / `6 resources still in use`，虽然退出码是 0，仍是实际缺陷。原始证据：`.local/verification/4.2-release-startup-v2/startup.stderr.log`、`4.2-release-startup-v2-02/startup.stderr.log`。第一轮没有进程暂停，因此不能归因于第二轮的暂停恢复。

这两份当前日志没有 verbose 对象名称。历史 `.local/verification/3.3-record-exit.log` 的同数目残留明确为三个循环 OGG 的 AudioStream、OggPacketSequence 及两种 Playback；当时只修复了录制结束清理，普通退出仍直接 `SceneTree.quit()`。本次旧包两次 verbose 补充运行（15 秒关闭／明确前台播放后关闭）没有再次复现，保留日志，不宣称稳定必现或已直接确认当前残留身份。最早一次诊断启动因临时 helper 的 UTC 字符串解析校验不匹配而未留完整日志，随后按自有 PID／路径／实际 StartTime 校正并正常关闭，未作为成功证据。

官方 4.7 实现支持异步混音清理的根因判断：

- [AudioStreamPlayerInternal](https://github.com/godotengine/godot/blob/4.7/scene/audio/audio_stream_player_internal.cpp)：离树只暂停，PREDELETE 才提交停止；`stop_basic()` 释放播放器持有的播放引用。
- [AudioServer](https://github.com/godotengine/godot/blob/4.7/servers/audio/audio_server.cpp)：`stop_playback_stream()` 标记 `FADE_OUT_TO_DELETION`，后续混音回合才移除播放项。直接退出可能不给这次清理留下运行机会。

旧包 verbose 中还有本机既有的第三方 Vulkan overlay 路径缺失等环境信息；没有改注册表、系统层或屏蔽日志，也没有把这些信息归到本次音频修复。

## 最小实现

- `FarmAudio.shutdown() -> void` 幂等：停止六个播放器并释放其 stream 引用；后续操作声／界面声返回 false，前台恢复不重启声音，用户保存的三个音量不变。
- 主入口增加统一 `_finish_exit()`：仅在保存成功、未加载的允许退出，或 HUD 明确放弃后进入。幂等终态取消待处理输入，禁用本场景处理及 GUI 输入；通知不再触发新保存。
- 调用音频 shutdown 后等待 100 ms 的独立实时 SceneTreeTimer，再给一次主循环清理机会，然后退出。没有阻塞主线程，也没有暂停现实时间或清除进度。
- 农场／设置保存失败仍返回原界面，声音与输入保留，允许重试；尚未获准离开时不会先清理音频。
- 录制专用退出保持现有实现；性能夹具可在采样全部结束后复用 `farm_audio.shutdown()`，再等待 0.1 秒及一帧，不在采样阶段执行。
