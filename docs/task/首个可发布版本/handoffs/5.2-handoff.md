## 发行准备与边界

- 版本拟 `0.1.0-rc.1`，目标是本地 Windows x86_64 可解压包，未签名、未上架。5.1 商务核验按用户要求暂缓，保留已有通知，不查询账户或付费订单。
- `scripts/package-release.ps1 -Commit <固定完整提交> -Version 0.1.0-rc.1` 只使用明确提交，新建 `.local/releases/<版本>-<提交前8位>/`；目录已存在就拒绝，不覆盖旧候选。
- 本地 `git clone --no-local --no-checkout` 后固定 detached commit，临时禁用 LFS 自动 smudge；仅复制提交引用的对象到独立 `.git/lfs/objects`，逐一核验对象与恢复后文件 SHA-256。干净副本不借用原 `.godot` / `.local` / 制作留档，也不共享原 LFS 缓存。无远端事实如实记录。
- 导入 / 导出分别通过固定 wrapper 子进程，立即检查退出码，并检查错误日志及跟踪源码漂移。成功后静态审计 PCK，再复制 exe + pck、中文说明、Godot LICENSE / COPYRIGHT、字体 OFL，生成 version.json、SHA256SUMS 和 zip 校验值。
- `scripts/check-release-pack.ps1` 按 [Godot 官方 PCK 目录格式](https://github.com/godotengine/godot/blob/4.7/core/io/file_access_pack.cpp) 读取当前独立非加密包。运行资源使用 all_resources 保留动态 load；只禁止开发 / 样片 / 测试 / 源文件与凭据，核验正式 art 资源及关键入口的映射存在。
- 静态旧包负例 257 条，其中 20 条样片及缓存、两个未包含的引擎文本通知；门禁拒绝符合预期。旧提交没有 config/version 时，打包在 clone / 引擎启动前拒绝。三个 PowerShell 文件解析通过。日志与 inventory 位于 `.local/verification/release-prep/`。
- `tests/native-game-window.ps1` 默认仍只操作原 `.local/builds/windows/Farm.exe`。外部候选必须显式 `-GamePath` 和 `.local/verification` 下 `-ProcessMetadata`，核对 exe 名和相邻 pck、元数据状态、确切路径、PID、启动时间；输入前依旧确认前台句柄，不扩大到任意窗口。
