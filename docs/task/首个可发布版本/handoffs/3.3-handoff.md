# 3.3 六田、正式院落与装饰布置交接

状态：实现、正式场景、普通发行重开与阶段影片归档完成。主代理统一提交，不对外发布。

## 状态与接口

- `Game/farm/decoration_catalog.gd` 是唯一物品 ID、门槛、槽类型和旋转契约，已随 3.2 提交 `8300f69`。`pot` 总计 3 篮；`flowerpot` 青菜 5／萝卜 3；`lantern` 青菜 10／萝卜 6。各一件，门槛不扣收获、重复解锁无副作用、合法已解锁状态不回收。
- 新 `decoration_state.gd` 只拥有三件物品的 `{unlocked,slot_id,quarter_turn}`；`snapshot/restore_snapshot/unlock/can_place/place` 不读写磁盘或依赖场景。严格拒绝未知字段、错类型、未解锁摆放、重叠、错误槽类型和非法旋转。
- `farm_store.gd` 升到严格 v2 `{version:2,farm:{…},decorations:{pot:…,flowerpot:…,lantern:…}}`。`save(farm_snapshot,decoration_snapshot)` 两参数均必传，不能省略装饰造成旧布置丢失；load/recover 返回两个状态和 `migrated`。
- v1 精确转换只补装饰（按已有累计解锁，位置为空），保留所有农场字段；首次写 v2 前保留原字节 `farm.v1.<SHA256>.json`，内容地址归档避免失败重试产生重复文件。上一有效备份也保留，坏档或较新版本仍按 2.3 锁定和显式恢复策略处理。
- 实际目录仍是 `%APPDATA%/Godot/app_userdata/我有一片田/farm/`。正常动作／确认布置统一保存完整状态；失败显示未保存并锁住操作，重试只存当前快照，不重复奖励。预览／取消不更改权威位置和磁盘。
- 4.1 已协调把界面偏好放在独立 `user://preferences/settings.json`，不为此升级 FarmStore v2。未来确实修改农场外壳时才显式升级版本、逐版本转换、校验完整结构，并保留装饰与农场；不要放宽 `data.size()` 或默认清空装饰。

## 场景、输入与后续接入

- `main.tscn` 的 `Environment` 实例为正式 `courtyard.tscn`。环境独占八个 Marker 坐标；本任务只存 `ground_01..04`／`hanging_01..04` 和季度旋转（地面 0–3，悬挂 0）。`get_decoration_scene` 返回正式 PackedScene。
- 新 `decoration_layout.gd` 拥有预览、确认／取消和可见槽判断；`decoration_hud.gd` 只发出意图。进入布置回全景并清农事工具；左键按下释放需同槽，拒绝拖动、双击与 UI 穿透；Esc／右键先取消预览再离开模式。失焦、退出、保存失败结束布置并恢复原物。
- 实际环境网格遮挡以共享 `TriangleMesh` BVH 检测，排除水／远景及不可见档位；启动 configure 预建缓存，布置及镜头事件只查询，无每帧扫描。最终八槽默认均可见可点，实测八槽热查询合计 **904 μs**（1280×720，RTX 4090 本机）；初稿冷建约 64 ms 已移出交互路径。3.5 改自动 LOD bias 不改变 Mesh，不失效缓存。
- `farm_layout.gd` 已移除旧院落体块、阶段标签、缩放成熟株幼芽和白球萝卜分支。每田独立 StaticBody3D、稳定 `field_id`，其 `Crops` 下固定 9 株；跨阶段 X/Z／朝向不变，按 CropVisuals 正式资源及 3／20／60 mm 萝卜入土量生成。仅 crop/stage 变化重建作物，浇水更新土和沟色。3.5 可按田的 Crops 控制显示，勿让 LOD 实例承担点选身份。
- 默认全景距离由 26 调至 29.5，保留原聚焦／过渡／平移缩放与限幅。HUD 左右田况／收获加浅纸底，夜间仍可读；4.1 接手最终布局与样式。
- `main.gd` 中 `farm_audio`／`window_activity`／`atmosphere` 已接 3.4：实际农事动作与工具／作物／布置切换发声；前后台控制音频和帧率；本地时间控制太阳、水和远景色；只给已确认灯笼挂点加灯光。录制会话才显式保持离线音轨，正常后台静音逻辑未变。
