## 状态契约

`snapshot() -> Dictionary` 返回深拷贝，结构只包含以下两个顶层键（磁盘格式版本应在外层封装）：

```gdscript
{
    "fields": {
        "field_01": {
            "crop_id": "", # 空田为 ""，否则 greens / radish
            "growth_seconds": 0.0, # 当轮累计有效生长秒数，含浇水增加值
            "last_settled_utc_seconds": 1800000000.0, # UTC Unix 秒
            "watered": false # 本轮是否已浇水
        },
        # field_02 ... field_06，同一结构，不能用数组排序作为身份
    },
    "harvested": {"greens": 0, "radish": 0} # 累计篮数，不消耗
}
```

`FIELD_IDS` 是固定稳定 ID 列表。累计数必须为非负整数，最大 `9007199254740991`（JSON 双精度精确整数边界）；达到边界后的收获拒绝且保留成熟作物。所有时间／生长必须有限且非负；空田生长必须为零、未浇水；有作物时生长不得超过时长，已浇水不得低于完整时长的 20%。恢复拒绝缺字段、非法 ID、未知额外 schema 字段、非法类型及不可能状态；不静默纠正。

初次 `new(now)`：01／02 空，03 成熟青菜，04 青菜 20%，05 萝卜 10%，06 萝卜 60%；全未浇水、累计为零、各田基准均为 `now`。2.3 必须仅在确认缺档且首次创建时把初态作为玩家状态；坏档不可用这个初态静默覆盖。恢复调用不自动结算，不产生任何奖励。

## 函数签名与结果

```gdscript
# crop_catalog.gd，静态调用，每次返回独立容器
static func crop_ids() -> Array[String]
static func definition(crop_id: String) -> Dictionary
# 返回 {id, name, duration_seconds}，未知 ID 返回 {}。
# greens: 青菜，1800 秒；radish: 白萝卜，5400 秒。
# WATER_PROGRESS = 0.2，YOUNG_PROGRESS = 0.35。

# farm_state.gd
func _init(now_utc_seconds: float = 0.0) -> void
func snapshot() -> Dictionary
func restore_snapshot(data: Dictionary) -> bool
func get_field(field_id: String) -> Dictionary
func settle(now_utc_seconds: float) -> Dictionary
func sow(field_id: String, crop_id: String, now_utc_seconds: float) -> Dictionary
func water(field_id: String, now_utc_seconds: float) -> Dictionary
func harvest(field_id: String, now_utc_seconds: float) -> Dictionary
```

`restore_snapshot` 在完整校验后深拷贝原子替换。JSON 反解析的整数值浮点篮数会转换回 `int`；返回 `false` 时当前完整状态不变。只由存储加载边界调用，不要在每帧、每次存档重试或操作后重复恢复旧快照；会话中“已加载”和版本／替换顺序由 2.3 负责。

`get_field` 返回独立视图（未知田 ID 为 `{}`）：原四字段加 `id`、`progress`、`remaining_seconds`、`stage`。空田阶段 `empty`，余时和进度为零；有作物的阶段为 `sprout`（幼芽 `[0,.35)`）、`young`（幼株 `[.35,1)`）、`mature`（成熟 `1`）。UI 可只使用视图，不能修改视图来操作权威状态。

`settle` 和动作的返回结构固定为 `{ok:bool, reason:String, changed_fields:Array[String], reward_crop_id:String, reward_amount:int}`。成功 `reason=""`；只有成功收获包含对应作物 ID 与数量 1，其他结果为空 ID／0。`changed_fields` 包含时间基准变化，因此空田和成熟田也可能在内；不能将此数组非空等价为可见阶段变化。

| 动作 | 成功条件／行为 | 拒绝原因 |
|---|---|---|
| 播种 | 空田；种子无限；新轮零进度／未浇水 | `invalid_crop`、`occupied` |
| 浇水 | 先旧态结算，仍生长且未浇水；增加总时长 20%，封顶成熟 | `empty`、`mature`、`already_watered` |
| 收获 | 先结算到成熟，累加对应作物一篮，整田清空 | `empty`、`not_mature`、`harvest_limit` |
| 所有动作 | 有效田 ID、有限非负 UTC | `invalid_field`、`invalid_time` |

无效动作是完整无操作，连时间基准也不提交：模块在候选副本结算后再判断。自然时间推进由上层定期独立 `settle(now)`；成功动作会统一结算全场再提交。成熟后停留不自动收获或开始下一轮。

回拨时不倒退生长与 UTC 基准；空田和成熟田也保留较新基准。回拨期间可播种／收获，但新轮继承较新基准，追平前不会重复使用旧时间。前跳无论多久都只让当前一轮成熟；无需离线逐帧重放。

## 后续集成示例

```gdscript
const Farm = preload("res://farm/farm_state.gd")
var farm := Farm.new(Time.get_unix_time_from_system())

# 唯一时钟入口取得 UTC；定期结算不要求逐帧扫描。
func update_farm(now_utc_seconds: float) -> void:
    var result: Dictionary = farm.settle(now_utc_seconds)
    if result.ok:
        refresh_field_views() # 从 get_field() 派生阶段模型与进度

func on_water(field_id: String, now_utc_seconds: float) -> void:
    var result: Dictionary = farm.water(field_id, now_utc_seconds)
    if result.ok:
        refresh_field_views()
        request_save(farm.snapshot()) # 重试写入这个已变更状态，不重放动作
```
