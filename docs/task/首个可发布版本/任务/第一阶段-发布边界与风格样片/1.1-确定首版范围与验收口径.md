## 实施方案

以 [实施方案](../../01-实施方案.md) 的范围表为一次简短确认基础。区分必须由用户决定的产品／发行选择与开发侧可自行确定的技术细节，不让无关发布账号阻塞可独立的玩法代码，也不带着未知的作物范围开始批量生成。

## 执行步骤

1. 重读固定风格、玩法草案、重要记录 004／005；核对本轮是否已有用户新决定。
2. 合并确认首版六田两作物三装饰、现实时间回访是否符合目标；展示首次即能收获／播种的安排，确认主要游玩节奏。区分可玩作物和参考中的环境植被，保留石桥、木船、水岸、远山等视觉层次，不把景物自动变成新玩法。
3. 记录发布渠道／地区、免费或收费、提交主体与期望日期；不能当场确定的项目标“待确认”，指定最迟在 5.1／5.3 前解决。
4. 确定实际可取得的目标硬件、系统、分辨率、画质与前后台行为。提出 60 帧目标及帧时间、启动耗时、持续运行检查口径，经确认后写明测量场景；不把 4K 视频要求当最低设备性能要求。
5. 固定最小首次／继续进入、声音和显示设置、退出与恢复入口，避免后续各自扩展菜单。确认存档是单份本地、无需联网。
6. 将确定结果写入实施方案与重要记录，调整受影响任务；获准实施后同步 `docs/design-baseline/gameplay.md`、`rules/project-context.md` 和旧费用授权描述，保留新旧事实边界。
