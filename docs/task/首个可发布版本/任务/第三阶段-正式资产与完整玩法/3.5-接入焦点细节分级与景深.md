# 3.5 接入焦点细节分级与景深

## 任务状态

- 状态：实现与验收完成，交主代理精确提交并同步总览；4.2继续独立性能长测。
- 所属阶段：第三阶段——正式资产与完整玩法。
- 前置任务：3.3、3.4；复用 1.2 的样片结论及 3.1／3.2 的资产交付。
- 关联任务：4.1、4.2、4.3。
- 是否可以并行：可与来源核验、素材整理并行；本任务修改镜头和场景呈现，不与其他任务同时写这些文件。

## 任务目标

让全景使用较低细节、聚焦田使用近景高质量模型，可见非焦点区域适度降级并配合温和景深；切换、缩放和操作始终清楚稳定，不改变农场数据。

## 实施前情况

- `Game/scenes/farm_camera.gd` 已有全景、聚焦、返回与微调，`main.gd` 维护当前田块选择；完整内容接入由 3.3 负责。
- `Game/art/crops/greens/greens_mature.glb.import` 已启用 `meshes/generate_lods=true`，尚无焦点区别控制或已验证的高低细节收益。
- `Game/project.godot` 使用 Forward+；当前主场景和相机没有景深配置。现有普通过渡和录制演示不能证明细节切换正确。

## 实施方案

遵循 [观察状态、工具路线与官方依据](../../01-实施方案.md#全景与聚焦的细节分级和景深)。优先自动网格 LOD 配合实例偏置，必要资产才显式切换同源网格；相机属性提供按深度的清晰带。焦点由既有选择状态驱动，控制仅属于显示，不另存一份田块或生长状态。

## 执行步骤

1. 核验 3.1／3.2 交付的高低细节、导入配置与轮廓检查记录，明确同屏数量；用调试统计确认实际存在可用 LOD，不能只查导入开关。
2. 建立全景、当前聚焦田和其他可见区域的显示策略。优先按田块／实例调节 `lod_bias`，以画面和实际图元确认效果；控制不足的资产才使用显式同源网格切换。若使用 MultiMesh，保持不同田块可独立控制。
3. 接入聚焦目标变更和镜头过渡：在放大前准备高细节；返回、快速换田、中途取消和缩放时及时恢复旧田，避免过期回调覆盖新目标。以阈值、迟滞或必要短过渡控制跳变，避免每帧重复加载和重建资源。
4. 给 Camera3D 配置 `CameraAttributesPractical`，依据目标田含作物高度的深度范围调整清晰带，平滑变化模糊距离与强度。全景关闭或减弱景深；聚焦时整块操作田保持清晰，旁田是否模糊取决于深度，不能用强模糊遮丑。
5. 布置、取消、失焦恢复与切换画质时维持可理解的显示状态；给 4.1 提供景深强度／关闭和细节策略的最小设置入口。关闭景深仍保留 LOD，点选碰撞及农场存档不随网格变化。
6. 在同一代表场景比较全高细节、仅 LOD、LOD 加景深，检查全景、聚焦及可见旁田的实际图元和帧时间；再测慢推、极限微调、快速换田、返回中断与阈值附近缩放，补必要的状态／输入回归。完整目标设备验收留给 4.2。
7. 在记录中固定采用方法、资产例外、实际参数、镜头与分辨率、对比结果；交给 4.1／4.2／4.3，不把离线展示当实时性能证据。

## 验收标准

- [x] 全景及非焦点可见区域确实使用较低细节，聚焦田的近景细节达到样片标准；有实际图元或网格级别证据。
- [x] 目标田全范围、界面和布置目标清楚，旁田仍可辨认和选中；原生景深无法按身份单独模糊同深度物体的边界有说明。
- [x] 慢推、快速换田、取消、返回和临界缩放无明显闪烁、轮廓跳变或加载卡顿，最终状态属于当前目标。
- [x] LOD 不改变作物阶段、存档或碰撞点选；关闭景深后细节分级继续有效。
- [x] 相同场景的三组对比有成本和画面记录，景深开销单独可辨；性能不足未被标为通过，交给 4.2 收敛。
- [x] 实际参数、例外、操作入口、执行记录和总览同步，3.5 独立提交。
