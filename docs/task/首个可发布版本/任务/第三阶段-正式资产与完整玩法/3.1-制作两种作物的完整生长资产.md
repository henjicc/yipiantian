# 3.1 制作两种作物的完整生长资产

## 任务状态

- 状态：已完成（完整阶段、高低档、固定入土量与实机验证通过；共享文档及提交由主代理收尾）。
- 所属阶段：第三阶段——正式资产与完整玩法。
- 前置任务：1.2；作物清单以 1.1 定稿为准。
- 关联任务：2.2、3.3、4.2、5.1。
- 是否可以并行：可与 3.2、玩法开发并行；只修改作物资源与独立组合场景，不同时修改主场景。

## 任务目标

交付青菜和白萝卜各三个可辨识、风格一致的生长阶段，使全景能判断田况、近景有足够表现，阶段切换保持同一根部与合理体量。

## 当前情况

- 任务开始时只有成熟青菜源与正式 GLB，路径为 `ArtSource/Crops/Greens/`、`Game/art/crops/greens/`；应复用 1.2 的验收成果。
- `docs/design-baseline/images/structure/radish.png` 等只是早期结构图，不是最终风格通过的三维输入。
- 草案不要求同拓扑连续变形，玩家和存档均不逐叶管理。

## 实施方案

按 [实施方案资产流程](../../01-实施方案.md#五资产生产流程与分工) 做阶段资产。整株优先，但若叶片／叶簇路线能更好保持株型和笔触，可由 Tripo 生成代表部件，再由 Blender 组合；交付仍是独立的阶段模型。合格成熟株不因“正式版”标签无故重生成。

## 执行步骤

1. 列出定稿作物×阶段矩阵，登记已有可复用项和缺失项；确定每阶段根部、尺寸、叶型与可见差异，不以缩小成熟株代替全部阶段。
2. 逐阶段以 [蔬菜参考](../../参考_蔬菜.jpg) 校对圆润叶型与淡彩质感，结合原高清图和固定提示词生成单体图，保持同品种和生长关系；萝卜根肩露出量明确，地下部分不无端建满高精度根系。
3. 检查图后按 [参数起点](../../01-实施方案.md#tripo-生成方式与参数起点) 提交 Tripo，保存真实任务参数与费用。叶片路线先验证一个有厚度、可连接的代表部件，再组装；不为每株每片叶子重复付费。
4. Blender 统一尺度、朝向、接地点与材质；检查薄叶、重叠、背面、法线、UV 和实际三角形。预算按 1.2 的目标镜头与同屏数量调整。
5. 导出阶段 GLB、贴图与独立组合资源；记录作物标识／阶段到资源的映射，交给 3.3 接入，避免两边同时改 `farm_layout.gd`。
6. 在同一真实场景中依次切换阶段，检查不跳根、不突然变品种、夜间可辨、全景不过密；按最多同时种植数量验证实例与材质成本。
7. 保存必要来源进正式源资产目录，完整生成与处理副本进入中文制作留档；将每一阶段的 Tripo 贡献写清楚。
8. 按 [细节分级方案](../../01-实施方案.md#全景与聚焦的细节分级和景深) 交付各阶段的近景与低细节能力：优先验证 Godot 自动导入 LOD，失真资产才从同源用 Blender 修减低细节。检查叶片不断裂、根部不漂移、阶段身份不变，记录实际面数与导入设置，供 3.5 使用，不逐档重新付费图生模型。

## 涉及内容

### 新增文件

- `ArtSource/Crops/`：缺失阶段的参考图、原始 Tripo 模型、可编辑源与来源说明。
- `Game/art/crops/`：采用的阶段 GLB／贴图；`Game/scenes/`：可复用作物组合资源及阶段映射，确切位置实施时登记。
- `制作留档/`：按作物及阶段分类的中文制作单元副本。

### 修改文件

- 成熟青菜资源仅在 1.2 结论要求时更新；`docs/design-baseline/asset-list.md` 记录实际采用项。

## 验收标准

- [x] 定稿两种作物全部阶段齐全，清楚区分品种与成长轮廓，非同一模型单纯缩放。
- [x] 连续切换根部稳定，纹理／材质一致；全景、聚焦、微调与暗处可辨。
- [x] 实际三角形、材质、贴图、尺寸和代表同屏数量有检查记录，重导入无缺失资源。
- [x] 没有增加逐叶模拟、骨架或额外运行服务；资源接入映射可交给 3.3。
- [x] 原件、输入、费用、处理与最终位置留档，来源交接给 5.1，资产表与总览同步。
- [x] 各阶段适用的高低细节已检查；极简幼芽如无需额外档有明确说明，近景与低细节切换不改变品种、根部或材质。
