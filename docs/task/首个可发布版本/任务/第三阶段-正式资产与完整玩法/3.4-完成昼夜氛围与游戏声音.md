# 3.4 完成昼夜氛围与游戏声音

## 任务状态

- 状态：待开始。
- 所属阶段：第三阶段——正式资产与完整玩法。
- 前置任务：2.3、3.2。
- 关联任务：3.3、4.1、4.2、4.3、5.1。
- 是否可以并行：可与 3.3 并行制作独立氛围和音频资源；主场景整合顺序需协调，避免同时改同一文件。

## 任务目标

形成温和、可读的昼夜变化和有完成感的操作声音；控制背景运行的打扰，保持现实时间生长独立于视觉和音频。

## 当前情况

- `main.tscn` 只有固定方向光、雾和环境；场地水岸为简化体块，没有随时间变化的系统。
- 当前无游戏声音，录制入口明确不录音；本任务加入声音不代表旧录制已经支持音轨。
- 玩法规则区分本地昼夜表现与 UTC 生长，首版不做实际太阳遮挡影响产量。

## 实施方案

Godot 负责光色、可见水面与轻微环境动态，不生成复杂天文／天气系统。音频采用明确可使用的来源或获准的生成方式，保留原始来源与处理记录；少量环境、播种／浇水／收获／界面声优先，背景音乐遵循 1.1 定稿。音量状态接口交给 4.1 接设置。

## 执行步骤

1. 以 [主界面参考](../../参考_主界面.jpg) 校准日间暖光、灰绿淡彩、水面和朦胧远景，再定义晨、昼、暮、夜的有限关键光色与平滑过渡，按本地时间取样；调试使用指定测试时间，不改变系统时钟。
2. 接入正式环境与灯笼的光照，检查夜间田况、工具和装饰可辨；纹理强阴影或高光问题回源修正。
3. 实现克制的水面和必要反馈效果，避免把参考图的静态笔触变成漂移噪声；暂停渲染或降低帧率不能改变生长结果。
4. 确定声音清单并核对来源，整理音量、循环接缝与格式；不给每个微动作叠多层高音量反馈。
5. 接入游戏事件和独立音量通道，重复点击／快速连续动作限制不必要叠音；按定稿处理失焦、最小化和恢复。
6. 在亮暗场景、全景与近景实测声音和画面，确认音乐／音效可静音并暴露设置接口；向 4.3 交接需要录制的声音通道。

- `ArtSource/`：采用音频／纹理的来源和可维护输入；具体位置实施时登记。

### 修改文件

- `Game/scenes/main.tscn`：最终集成灯光、环境与声音；独立资源确认后再合入。
- `docs/design-baseline/asset-list.md` 与开发准备：补声音资源和验证入口。

## 验收标准

- [ ] 四种代表时段与过渡下均能辨认田况和操作；没有引入日照产量、天气或联网服务。
- [ ] 昼夜变化／后台渲染不影响生长与离线结算结果。
- [ ] 操作声不爆音、不持续重叠，循环无明显接缝，音量／静音和失焦策略有效。
- [ ] 音频与新增素材来源可交给 5.1 复核，界面和录制任务知道音轨边界。
- [ ] 画面与声音真实检查完成，采用资源、测试入口及总览同步。
