# 5.1 核对资产权利与渠道提交要求

## 任务状态

- 状态：用户暂缓商业／授权核验；前期交接已形成，待最终来源归档，非完整验收通过。不阻塞研发或本地包。
- 所属阶段：第五阶段——发行候选与交付。
- 前置任务：1.1 后可开始；完整验收还需 3.1、3.2、3.4、4.1 的最终采用清单。
- 关联任务：全部资产任务、4.3、5.2、5.3。
- 是否可以并行：可提前与开发／资产制作并行；持续核验来源，最终清单齐全后再完成，不到出包时才调查。

## 任务目标

为最终采用的代码、模型、纹理、图片输入、字体与音频保留可核验的来源及使用依据，并明确选定渠道提交条件，使发行包和宣传素材具备真实交付基础。

## 当前情况

- Godot 与项目技能有许可资料，正式发行中的声明尚未整理；现有界面调用系统字体，不代表可把该字体文件随包分发。
- 成熟青菜有生成任务和处理记录，馆藏参考有 `docs/design-baseline/sources.md`；当前账户产物条件、所有输入来源及新素材尚未完成发行核验。
- 尚无明确渠道、地区、售价、提交主体或签名方案；不能把“商业推广项目”推断为某个商店已允许上架。

## 当前执行边界

用户最新第 7 条要求暂时不处理商用授权。下列商业调查步骤暂不执行，已有来源记录保留；不据此宣称权利核验通过，也不因此更换参考或重生成合格素材。该任务商业检查不再是 5.2 本地出包的阻塞依赖。

## 原实施方案（商业步骤暂缓）

先查必需条款再批量采用，保持一份轻量中文来源／提交清单；不发表无依据的法律结论。按本次具体账号与实际使用的产品条款核对，不把插件说明、订阅付费或公开下载等同于全部权利。未知关键材料更换来源或请用户补充，不通过伪造来源解决。

## 执行步骤

1. 按 1.1 的本地可解压 Windows 发行包核验通用许可与来源，记录查阅日期和实际账户适用条款；特定商店、发行主体与地区未指定，列为本轮不适用，不虚写平台提交通过。
2. 提前核对 Tripo 实际使用入口及当前账户方案对应的产物条款，检查固定图与生成链的输入来源；公开文档不够时注明需要账户／合同依据，不读取或公开密钥。
3. 为已采用的模型、贴图、字体、声音、图标和引擎组件登记来源、版本、使用依据、必要署名和是否进入发行包；参考研究图与真正打包资源分开。
4. 按 [Godot 官方许可说明](https://docs.godotengine.org/en/stable/about/complying_with_licenses.html) 整理引擎及对应第三方声明，连同其他资源通知提供给 4.1／5.2；不用工具技能的许可证替代资产许可证。
5. 核对选定渠道是否要求签名、评级、主体材料或生成内容披露，缺哪些写哪些；证书和发布服务费用不从资产生成授权直接推导，准备清楚需求后再按用户授权办理。
6. 在最终采用清单稳定后逐项复核，标记无依据素材并处理替换，给出可随包声明与渠道提交清单，不把未核验项标通过。

## 涉及内容

- `ArtSource/`：对应资产的正式来源说明；`docs/design-baseline/sources.md`：必要的真实来源修订。
- 预计 `docs/` 中一份中文发布来源／提交清单，以及 `Game/` 或随包的中文署名和许可入口；实施时在本任务登记确切文件，不创建重复台账。
- `制作留档/`：详细合同／生成记录中的可公开证据副本按敏感性处理；正式必要来源摘要仍要随仓库保存。

## 验收标准

- [ ] 已采用资源逐项有来源、用途、使用依据与必要声明，未解决关键权利项为零或已替换。
- [ ] 系统字体、音频和图片输入没有被默认当作可自由分发资源。
- [ ] 引擎及其随包组件声明有可靠依据；Tripo 与其他工具贡献按事实区分。
- [ ] 本地发行所需来源与许可明确；未来商店账号／签名／主体资料未指定的边界如实记录，不宣称可提交任意平台。
- [ ] 最终采用清单已覆盖 3.1、3.2、3.4、4.1，声明交给 5.2／5.3，总览同步。
