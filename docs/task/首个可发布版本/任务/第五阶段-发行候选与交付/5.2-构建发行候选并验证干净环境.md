## 任务目标

从可追溯的完整源码生成真正可交给玩家／甲方的 Windows 发行候选，证明移出开发仓库仍能运行、保存和回访，且没有夹带开发内容。

## 当前情况

- `scripts/godot.ps1 ExportWindows` 输出 `.local/builds/windows/Farm.exe` 与 `Farm.pck`，外置数据包必须保留。
- `Game/export_presets.cfg` 使用 `all_resources`，未启用签名和程序资源自定义；录制节点位于 `Game/development/` 且主控制可以显式加载，不能只隐藏按钮就认定已排除开发能力。
- Git LFS 已配置但无远端，原始素材、录屏、缓存和测试输出在忽略区；需要验证没有隐藏构建依赖。

## 实施方案

沿用固定引擎及匹配模板，补必要的发行配置与可重复打包入口，不更换引擎。按渠道选择解压包或实际要求的分发形式，加入版本、图标、许可、操作／存档说明和校验值。开发录制只留开发入口，不作为玩家发行依赖。

## 执行步骤

1. 固定候选版本与完整提交，确认 LFS 对象存在；在独立干净工作副本导入并构建，不使用原工作区的 `.godot/`、`.local/` 或素材留档。
2. 补版本、图标和定稿导出设置，按 5.1 决定处理签名；没有签名就如实记录，不声称已签名或必定免系统提示。
3. 将录制／测试入口与正式运行隔离，核查发布资源清单：开发节点、测试档、原模型源、凭据、远程执行能力和 FFmpeg 不进入玩家包，正式场景引用仍完整。
4. 将可执行文件、数据包、所需许可证、中文操作／恢复说明、版本变更与校验值打包；不能只复制 exe，不能依赖本机绝对路径。
5. 在仓库外的干净目录及约定目标机器启动，覆盖中文／空格路径、非管理员运行、声音／显示、播种保存、关闭重开、离线回访和正常退出。
6. 验证没有 Godot／Blender／Tripo 开发安装和生成账号也能运行；核查网络需求与设计一致，试验数据不污染玩家存档。
7. 记录构建命令、引擎／模板版本、提交、包内容、哈希、测试环境与已知问题。若已有远端则核验 LFS 上传及独立克隆；无远端只报告本地干净副本验证，不伪称异机同步。

## 涉及内容

### 修改文件

- `scripts/godot.ps1`、`Game/export_presets.cfg`、`Game/project.godot`：必要的发行配置与入口。
- `Game/scenes/main.gd` 及 `Game/development/` 边界：确保发布构建不暴露开发录制路径；测试验证实际产物。
- README 与开发准备：正式构建／运行／存档说明。

### 新增文件

- 仅在当前入口不足时增加最小打包脚本、正式图标、中文随包说明与许可证汇总；确切路径实施时登记。
- `.local/builds/`：候选包与构建日志；`制作留档/`：交付副本与验证证据，均不入 Git。

## 回退原则

候选包按版本独立保存，不覆盖用户正在运行的旧 exe。修复后生成新候选及校验值，保留失败原因；数据回退按 2.3 的格式边界处理，不用删档修复兼容问题。
