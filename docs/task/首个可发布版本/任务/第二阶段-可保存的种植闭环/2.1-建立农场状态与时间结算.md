# 2.1 建立农场状态与时间结算

## 任务状态

- 状态：已完成（纯规则模块与回归通过，界面／磁盘集成由 2.2／2.3 接续）。
- 所属阶段：第二阶段——可保存的种植闭环。
- 前置任务：1.1。
- 关联任务：2.2、2.3、3.3。
- 是否可以并行：可与 1.2、5.1 并行；本任务不修改资产或主界面。

## 任务目标

建立不依赖相机、网格或帧率的农场状态与确定性规则，让播种、浇水、生长、收获和未来存档共享唯一状态来源。

## 当前情况

- `farm_layout.gd` 仅按行列创建田块并实例化成熟作物，`field_index` 用于拾取；无作物状态或时钟入口。
- `main.gd` 的 `selected_field` 是界面选择，不应被当作存档数据。
- `rules/farm-simulation.md` 已约定 UTC、回拨不倒退、动作先结算、离线上限为单轮成熟及隔离测试；具体数值由 1.1 定稿。

## 实施方案

在 `Game/` 内用带类型的状态／规则模块与静态作物配置实现最小闭环，状态可序列化但本任务不做磁盘读写。时间由单一入口提供并可在测试注入，函数输出动作是否成功及变更，不由动画或资源节点发奖。

## 执行步骤

1. 明确田块稳定标识、作物标识、空地／生长／成熟、有效进度、UTC 秒结算基准、当轮浇水和累计收获字段；写出允许动作及无效动作表。
2. 建立青菜的静态定义和与网格独立的阶段映射；为后续萝卜使用相同定义结构，不提前创建通用系统框架。
3. 实现“结算到指定时刻”及播种、单次浇水、收获；按定稿时长和阶段边界计算，超过成熟不累积下一轮收益。
4. 实现回拨时保留较新基准、前跳成熟封顶、重复调用无重复收益；动作先按旧状态结算，浇水不得对空田／成熟田／已浇水田生效。
5. 增加无窗口规则测试：阶段前后边界、同一时间不同分段、一次／重复浇水、成熟临界收获、回拨／追平／前跳、重复结算和非法作物标识。
6. 在任务记录中给出确切代码文件、状态字段与测试入口，交接 2.2／2.3，不要求下游重新推断规则。

## 验收标准

- [x] 可在无场景／无渲染环境验证种植到收获；稳定标识不依赖节点索引或位置。
- [x] 相同起点和经过时间的在线分段、离线一次结算结果一致。
- [x] 阶段边界、回拨／前跳、重复动作、成熟封顶均通过测试，收益不重复。
- [x] 无效操作不改变状态，作物定义不被玩家操作改写。
- [x] 后续可直接使用的状态字段、函数入口和测试命令见 [2.1 交接](../../handoffs/2.1-handoff.md)；总览由协调代理统一同步，避免并行覆盖。
