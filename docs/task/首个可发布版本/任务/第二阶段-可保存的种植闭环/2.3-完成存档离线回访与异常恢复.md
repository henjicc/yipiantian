# 2.3 完成存档离线回访与异常恢复

## 任务状态

- 状态：已完成，待主代理统一提交。
- 所属阶段：第二阶段——可保存的种植闭环。
- 前置任务：2.2。
- 关联任务：3.3、3.4、4.1、4.2、5.2。
- 是否可以并行：可与 3.1／3.2 的资源制作并行；涉及主场景启动／退出时独占修改。

## 任务目标

让种植闭环在关闭、重新打开、休眠和离线后仍然正确；保存失败、坏档或版本不支持不会静默清空玩家农场。

## 当前情况

- 仓库没有 `user://` 游戏存档实现；录制握手文件属于开发工具，不是农场数据。
- 2.1 将提供稳定状态和可控 UTC 结算，2.2 提供操作入口；当前 README 与模拟规则要求存档和测试路径隔离。
- 尚无旧正式玩家档需要兼容，不能借此省略首个格式的版本号与校验。

## 实施方案

单份版本化本地存档，保存玩法状态而非节点引用；采用临时写入、验证和安全替换，保留上一有效数据。普通动作及时触发保存，写入串行且不让旧快照覆盖新状态。具体文件操作先查固定版本 Godot 文档并在 Windows 隔离目录验证。

## 执行步骤

1. 在 2.1 状态基础上定义首个格式、字段范围、稳定标识、UTC 秒和版本；登记真实 `user://` 位置及隔离测试入口。
2. 首次缺档时创建初始农场并保存；正常重开仅恢复已有状态。损坏、空内容、不支持版本与真正缺档分别处理。
3. 实现临时文件写入／校验／替换及有效备份；故障时保留旧档，记录原因并给出可理解的重试或恢复入口，不自动创建新农场覆盖原档。
4. 将成功动作和退出接入保存。未保存的内存变更保持明确状态，重试只保存当前快照，不重新执行收获；退出失败需真实反馈。
5. 加载、休眠恢复和重新获得活动状态时用同一个结算入口推进；不依赖后台帧循环，不自动收割或多轮发奖。
6. 用隔离目录与指定时间测试：往返一致、重复加载、回拨／前跳、长离线、临界成熟、写入中断、只读／权限失败、截断文件、未知版本与备份恢复失败。
7. 用实际独立程序走完播种、退出、回访、收获和再次重开；记录证据与存档位置，交接 3.3 新字段接入规则。

## 涉及内容

### 新增文件

- `Game/`：存档读写与校验职责；`tests/`：存档恢复、故障与离线回归。
- `.local/`：仅测试数据与错误证据，不入库、不覆盖玩家数据。

### 修改文件

- 农场启动、成功动作和退出路径，必要的保存状态界面。
- `docs/development-setup.md`：真实存档路径、测试入口与恢复步骤；正式操作说明随实际实现更新。

## 数据与恢复要求

一旦建立格式，3.3 增加解锁与布置字段必须明确版本处理及旧测试档兼容。无法支持的较新档保留原件并阻止覆盖。任何测试不改系统时钟，不删除真实玩家存档；回退代码不能连带重置已保存进度。

## 验收标准

- [x] 保存后重开恢复一致，首次奖励不重发，已收获田不会再次发奖。
- [x] 同一跨度的在线与离线结果一致，休眠和回拨／前跳满足定稿语义。
- [x] 写入中断／失败保留旧有效档；坏档和未知版本不会被静默重置覆盖。
- [x] 恢复与重试不会重复执行玩法动作，失败反馈可见且事实准确。
- [x] 自动测试及真实退出重开检查通过，恢复步骤、格式边界见交接，总览由主代理同步。
