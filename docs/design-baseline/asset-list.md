# 首批资产与计划输入

数量是制作方案的起点，不是已完成模型；图中的船桥、花树和村落不逐件照搬。

| 优先顺序 | 对象 | 当前准备与制作方式 | 验收重点 |
|---|---|---|---|
| 原型 | 田块、道路与镜头关注点 | Godot 简单几何体，两块田先验证 | 全景选田、聚焦操作、返回与微调不冲突 |
| 样式小样 | 一种田块及边缘、石路、短篱笆 | Blender 模块，先统一尺度与枢轴 | 接缝、点选与前景遮挡；不复制画面里的每一块碎石 |
| 样式小样 | 青菜的幼芽 / 幼株 / 成熟 | 优先 Tripo 整株阶段；必要时 Tripo 叶片 + Blender 组装，按 A 青菜固定风格 | 品种、根部、体量与质感一致；离散阶段不要求同拓扑 |
| 样式小样 | 一座民居 | Tripo 静态外观或部件，Blender 校准结构与尺寸，保留微调需要的侧面 | 占画面比例、屋瓦尺度和笔触密度；不因此实现室内或开门 |
| 完整试玩 | 白萝卜三个阶段 | Tripo + Blender 阶段整理，与青菜保持不同叶型 | 根肩露出量、生长轮廓和辨识度 |
| 完整试玩 | 粗陶罐、小花盆、小灯笼 | Tripo 代表物件，Blender 修整；Godot 灯光 | 固定装饰位置、解锁状态与保存；不依赖真实物理模拟 |
| 氛围 | 水岸、水面、少量树与远景层次 | 岸石 / 植被按需 Blender，水面及表现按 Godot 当前需求实现 | 画面有留白，旋转不露明显断面，背景不盖过田块 |
| 按需 | 独特复杂树桩或观赏石 | 只有具体轮廓需求出现时，再以干净单体图试 Tripo | 输入笔触不被重建为破洞；记录成本与实际修整量 |

图片、结构源与游戏资产分开：本包的 PNG / JPG 是设计依据；正式 `.blend` 放 `ArtSource/`，采用的 GLB 放 `Game/art/`。不把博物馆图、图中文字或生成 HUD 直接塞入游戏。GLB、材质、碰撞和同屏性能随实际资产验证。

整体风格已固定为 [A 全景 + A 青菜](style-guide.md)。用户补充平台推广目标后，Tripo 在合理范围内优先，不再仅承担复杂装饰；完整规则与制作留档要求见 [资产工作流](../asset-workflow.md)。

## 首批制作交接

下表是接下来实施的文件约定与验收顺序，不表示这些模型和功能已经完成。以整株阶段交付，不要求玩家或存档逐叶管理。

| 顺序 | 交付单位与位置 | 完成标准 |
|---|---|---|
| 1 | 成熟青菜 Tripo 小样；原始输出先在 `.local/experiments/tripo-greens-v1/`，完整副本在本地 `制作留档/` | 正背面、叶片间隙、纹理与面数检查；记录来源和真实费用，不生成整座农场网格 |
| 2 | 采用后源文件 `ArtSource/Crops/Greens/`；三个阶段 `greens_seedling`、`greens_young`、`greens_mature` | Tripo 原始模型保持独立，Blender 整理源可编辑；同根部与尺度，阶段变化合理；无逐叶骨架要求 |
| 3 | 正式 GLB 与纹理放 `Game/art/crops/greens/`，组合场景放 `Game/scenes/` | 在 Godot 检查可辨识度、昼夜与相机转动；必要碰撞按田块设置，不给每片叶子配碰撞 |
| 4 | 两田原型、一种作物、全景 / 聚焦与返回 | 同一真实三维场景里镜头移动；接入种植与存档前先确认点选不穿透 |

先用一个小样决定整株或叶片路线，随后补阶段；不同时批量铺开作物、房屋与装饰。单株尺寸先用田块体块确认，预算依据实际同屏数量和近景检查，不把试样的面数参数写成全项目上限。
