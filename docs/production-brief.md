# 我有一片田：玩法、操作与首轮制作草案

> v0.1 · 2026-09-17。根据本地 starter pack 提炼，并补充可执行的首个可玩切片建议。**当前工程仍为空白三维场景；下文的切片规模、数值和画风候选尚未被用户选定，也尚未实现。** 后续确认与体验结果直接更新本文，避免另建相互冲突的玩法清单。

## 1. 要做的体验

拥有一小块会随现实时间生长的田，偶尔照料、收获，逐步把它布置成喜欢的样子。重点是看得清、点得准、愿意回来看看；不通过枯死、催促和错过奖励制造负担。

已确认的产品基线是 **Godot、Windows 普通窗口、三维微缩田园**；正式桌面壁纸宿主后置。江南民居、灰瓦粉墙、旧木竹篱和青绿色植物是当前创意方向。具体玩法仍需以本次制作范围为准。

资料包提出的完整循环是：整理土地 → 播种 → 照料 → 生长 → 收获 → 加工或交易 → 解锁 → 布置。建议先做其中可独立体验的一圈：**播种 → 可选浇水 → 观察生长 → 收获 → 再播种**。

## 2. 首个可玩切片建议

以下是为了尽快验证手感而提出的默认草案，数值集中调整，不预建配置编辑器。

| 项目 | 建议范围与行为 |
|---|---|
| 场地 | 3 行 × 4 列，共 12 个固定田格；每格独立点选，一个作物状态对应一个田格 |
| 作物 | 一种叶菜，暂以圆白菜轮廓占位；正式品种待确定，不能将圆白菜图当成原资料中的大白菜 |
| 生长外观 | 幼芽、幼株、成熟三种模型状态，另有空地；同一物种、同一根部位置，阶段大小连续 |
| 种子与产出 | 首轮不计种子成本；成熟后一次收获计数 +1，田格回到空地。不建立商店、价格或库存系统 |
| 生长时长 | 建议现实 60 分钟成熟；有效生长进度达到 35% 时转幼株，达到 100% 时成熟。开发验证使用隔离的可控时间，不修改系统时钟 |
| 浇水 | 每次种植周期可浇一次；先结算到操作时刻，再增加 10 分钟有效生长时间，最多达到成熟。重复浇水不叠加；收获后下一次种植重新允许浇水 |
| 低压力 | 不浇水也会正常成熟；成熟后保留，直到主动收获；不枯死、不腐烂、不自动收获 |
| 时间表现 | 时钟显示现实本地时间；第一阶段先用固定日间光照验证交互。简单昼夜光照随后加入，不因此引入日照影响生长、天气或季节 |
| 本地存档 | 保存各田格、浇水标记、有效生长进度、结算时间与收获计数；关闭、休眠后回来能恢复 |
| 场景装饰 | 民居、篱笆、水岸等先是固定背景；图片中出现不代表可以点击、进入、搬动或建造 |

浇水在这版中是一次轻量加速行为，用于验证“照料有反馈”，并不模拟水分蒸发。若体验说明这一机制太机械，再调整它；首轮不同时叠加肥力、湿度、日照和疾病。

## 3. 操作方式

| 输入或情境 | 首轮行为 |
|---|---|
| 点击底部“播种 / 浇水 / 收获” | 切换工具；选中项同时有文字、图标和形状反馈 |
| 指针移到田格 | 显示田格边界；根据当前工具和田格状态表现能否操作，不能只靠颜色区分 |
| 左键点击空田格，当前为播种 | 新增幼芽状态，开始计时 |
| 左键点击未成熟且本周期未浇水的作物，当前为浇水 | 结算旧进度，应用一次加速，标记已浇水并给短暂水花反馈 |
| 左键点击成熟作物，当前为收获 | 收获计数增加一次，移除作物并清空该周期状态 |
| 操作条件不满足 | 不改变资源和时间状态；保留当前工具，给简短的无效操作反馈，不强制弹窗 |
| 右键或 Esc | 取消工具，回到观察状态；仍可悬停查看边界，不改变田格 |
| 点击 UI、窗口外按下后移入、按住拖过其他田格 | 不穿透 UI、不补触发、不连续操作；一次点击只处理一个有效目标 |
| 窗口失焦或取消输入 | 清除尚未完成的按下状态；回来不会执行之前遗留的操作，作物时间继续推进 |

点击建议在同一田格内按下并释放时确认。操作动画展示成功结果，不由动画结束再次扣数或收获。首轮只做点击；原资料中的拖拽播种、刷过浇水、范围收获、扇形施肥是后续提效候选，采用时再规定路径去重和取消语义。

镜头从固定轴测或弱透视开始，让所有田格在目标窗口内可见。暂不加入 WASD、角色跟随或自由旋转。若实际试玩需要，再增加有限缩放和平移；布置模式中的 90° 旋转只在布置功能进入范围后实现。

## 4. 时间、离线与存档语义

- 生长按经过的有效现实时间计算，持久化使用 UTC 时间戳；本地时间只负责时钟和后续昼夜表现。后台低帧率、失焦、休眠和关闭不改变同一时间跨度的生长结果。
- 离线回来直接结算到当前状态，最多到成熟；一次种植最多等待一次主动收获，不因离线几天自动发放多轮产物。
- 操作先按旧状态结算，再执行动作。浇水可能直接跨过成熟边界；成熟作物不再消耗浇水机会，也不追加收益。
- 回拨时不产生负进度，保留较新的结算基准，等时钟追上后继续推进；向前跳跃最多令当前作物成熟，不引入联网校时或反作弊。实现时验证“回拨后恢复”不会重复计算同一时间段。
- 首次没有存档与存档损坏是两种情况。损坏或不支持的版本不得静默清空并覆盖原文件；保存失败要保留上一份有效数据并反馈实际结果。
- 成功改变田格或收获计数后及时保存，不能只等正常退出。存档格式、稳定标识和中断写入策略在实现时按 [模拟与存档规则](../rules/farm-simulation.md) 落实；测试使用隔离路径。

## 5. 首轮画面与风格比较

以下是重新生成的**单张运行界面概念图**，不是 Godot 截图，也不代表已经实现的画质或功能。两张保持相近的镜头、田格和 HUD，主要比较风格，避免拿完全不同的场景判断喜好。

### A：材质细节较多的手作微缩感

![A：手作微缩运行界面参考](visual-references/runtime-a-v01.png)

石路、土壤和植被细节较丰富，氛围自然；代价是画面频率较高，正式制作容易把时间花在小纹理上，需要控制地面和边缘装饰。

### B：形体简化的手绘三维感（推荐候选）

![B：简化手绘三维运行界面参考](visual-references/runtime-b-v01.png)

叶片、泥土和建筑形体更清晰，适合小窗口和重复出现的作物。建议以 B 为后续小样的起点，再由用户判断是否足够温润、是否过于卡通；目前不记为已经选定。

两张图仍有需要制作时纠正的地方：边缘略有虚化、背景植物偏多，部分田格画了多株幼芽；这些不成为功能或数量要求。实际田格要始终清晰，前景篱笆不得遮住点击区域。工具栏、时钟、图标和字体应在 Godot 中重新制作，不裁切生成图作为 UI。初始田格状态由玩法决定，不照抄图中的阶段分布。

### 风格怎样固定

先选定一张主参考，配合以下文字约束；后续生成带上该图作为风格参考，并在同一约束内修改。仅重复“可爱、低多边形、江南”几个词不足以保证一致，也不能靠固定提示词保证每次结果相同。

| 维度 | 当前候选约束 |
|---|---|
| 造型 | 轮廓略圆润、比例适度夸张、叶片和瓦片成组概括；不追求显眼三角块面 |
| 材质 | 哑光陶、灰瓦、粉墙、旧木、竹、土和叶片；保持材质差异，避免统一塑料高光 |
| 颜色 | 米白、灰瓦、旧木棕、暖土色、苔绿与青绿水色；高饱和度仅少量强调 |
| 细节 | 优先轮廓和大色块；远处看不见的叶脉、编织、裂纹不做成密集几何 |
| 文化元素 | 家常江南院落；不默认加入欧式谷仓、风车、宫殿屋顶、仙侠悬浮物 |
| 光照 | 柔和、中性日光作为比较基准；夜间可读性后续用实际引擎验证，不能把强阴影画死在底色贴图上 |

随后用“一格田 + 一种作物的阶段 + 一个简单道具”在 Godot 组成小样，按目标窗口和同一镜头截图比较。用户判断轮廓、材质和氛围，开发侧判断结构、导入、交互与性能。小样通过后常规资产按同一标准推进；需要用户选的是整体感觉，不是每个技术参数。

## 6. 图片怎样服务三维资产

建议采用 **场景风格参考 → 单体设计图 → 按用途选择 Blender / Tripo → GLB → Godot 实际画面检查**。运行画面决定整体观感，单体图给建模提供结构；不要把整张农场截图交给 Tripo 生成一个无法独立操作的场景模型。

- **适合 Tripo 的独立复杂道具**：先通过图片确定外观，再以干净的单体图生成候选，检查隐藏面和材质后使用或修整。
- **精确模块和简单物件**：田格、篱笆、屋顶、陶盆等按共同风格直接在 Blender 制作通常更可控；不要求每件都付费生成。
- **多阶段作物**：先定同一品种的成熟轮廓及阶段关系，再用 Blender 共享叶片、根部和比例。不能每个阶段各自生成，最后靠缩放勉强拼接。

下面是单体输入示范：干净背景、完整轮廓、三分之四视角、柔和光照，无场景和 UI。

![单体资产参考：修订后的灰青庭石](visual-references/rock-input-v02.png)

这张庭石图用来说明输入规范，**尚未通过 Tripo 重建验证**，也没有批准将石头纳入首版。造型已经很简单，正式制作可能直接用 Blender。第一版把三个鼓包画成了近似叠石，修订后改为单一连续体；这是“先检查结构，再花积分生成三维”的具体例子。单张图仍不能证明背面、底面和真实尺寸正确。

背景、视角、多视图、提示词模板及游戏资产检查的详细规范，统一维护在 [三维资产工作流](asset-workflow.md#图片驱动的制作流程)。本轮未执行 Tripo 付费请求。原始提示词、参考关系和目视检查结论见 [生成记录](visual-references/generation-record.json)。图像工具未返回可记录的具体模型版本或种子，不承诺像素级复现。

## 7. 制作顺序与验收

| 阶段 | 做到什么 | 怎样判断可以继续 |
|---|---|---|
| 1. 可玩的体块 | 12 格占位、单种作物、三种工具、计时、离线恢复和存档 | 能完整播种、照料、收获、重开恢复；无重复收益、错格或 UI 穿透；时间与损坏存档边界通过 |
| 2. 统一美术小样 | 一格正式田地、一种作物阶段、少量代表材质和轻量 HUD | 目标窗口下点选清楚，阶段根部不跳、风格统一；与选定参考在相近镜头下比较 |
| 3. 完整小场景 | 按已选风格补必要背景，加入简单昼夜表现，导出 Windows 版本 | 夜间仍能照料，前后台行为符合时间规则，独立程序运行正常；记录实际性能，不以本机显卡富余代替预算 |
| 4. 体验后扩展 | 根据试玩反馈选择下一项，如拖拽操作、布置或第二种作物 | 每次说明解决什么体验问题，不一次搬入整个资料包 |

最终判断包括“操作是否舒服、收获是否有反馈、隔一段时间回来是否有变化”。截图只能评估画面，不能证明玩家愿意次日回来；是否扩展内容要结合真实试玩。

## 8. 保留但不自动进入首版的方向

| 资料中的方向 | 当前处理 |
|---|---|
| 约 36 格、6 种作物、5 阶段；另一处又写 8×8 | 作为后续内容规模候选；首轮建议 12 格 / 1 种 / 3 个可见阶段，不兼容两套默认规模 |
| 水田、棚架、果树，稻麦、白菜、萝卜、茄子、葫芦 | 需要不同结构和行为；从第二种作物开始再评估，不全部套叶菜模型 |
| 肥力、真实日照遮挡影响生长、天气 | 与视觉昼夜分开；需要说明玩法价值和离线近似后再实现 |
| 14～21 天一季、四季换景 | 原资料与“季节暂缓”有冲突；暂缓，不与现实昼夜混为同一时钟 |
| 自由布置、12 件装饰、清理和扩地 | 保留为表达所有感的方向，后续明确占地、碰撞、取消与保存规则 |
| 猫、鸡、村民、任务、订单、加工、交易 | 不从概念图自动推导角色、动画、寻路或经济系统 |
| 桌面宿主、多屏、云存档、联机 | 不属于首轮窗口版切片 |
