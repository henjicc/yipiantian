# 三维资产的工具分工与选择

> 2026-09-17 制定。适用当前 Windows 窗口版、江南微缩田园方向；这是制作决策基线，不代表表中资产都进入首版。安装版本、调用入口和已完成测试见 [开发准备](development-setup.md)。

## 选择原则

**图片生成工具负责风格和单体设计参考，Blender 负责可控的模型制作与修整，Tripo 负责独立复杂造型的候选生成，Godot 负责场景组装、玩法表现和最终验收。** 不要求每个资产经过所有工具，也不按“哪个工具更新”决定用途。

判断顺序：先看是否需要精确尺寸、拼接或连续变化，再看造型复杂度，最后比较生成、人工修整、导入和后续修改的总成本。规则明确、反复复用的结构优先直接建模；难以用简单结构描述、又不依赖精确部件关系的单体优先考虑生成。简单物件即使能生成，也未必值得付费；低多边形也不自动等于低成本或符合本项目画风。

以下分工是结合工具能力与本项目需求的判断。Blender 的基本自动化已实测，Godot 当前仅完成基础工程配置；Tripo 的生成质量、动画质量，以及完整的 Tripo → Blender → Godot 链路尚未实测，不能称为生产验证通过。

## 按资产类型选择

| 类型及例子 | 首选制作方式 | 其他工具的作用与选择理由 |
|---|---|---|
| 原型体块、地块占位、交互范围 | Godot 基础几何体 | 先验证大小、构图和点选。需要正式轮廓时再换 Blender 模型，不为占位付费生成；简单体块符合最终风格时可以保留 |
| 田畦、田埂、院墙、石板路、篱笆、桥面等拼接件 | Blender | 精确控制尺寸、接缝、枢轴，复用部件；Godot 负责摆放与组合。避免分别生成相邻模块再花时间消除接缝 |
| 民居、亭棚、屋顶、门窗等建筑 | Blender 主体与模块 | Tripo 可提供独立静态建筑的造型候选或局部装饰，但需要开门、进入、替换屋顶或对齐网格时，相关结构应分件制作；建筑比例与江南形制仍需检查 |
| 作物幼苗到成熟的阶段资产 | Blender 共享部件、阶段模型或形变 | Godot 按生长状态驱动显示。统一根部、叶片语言和阶段比例，避免各阶段独立生成造成换物种、位置跳变；Tripo 可供成熟轮廓参考，但不能取代阶段衔接设计 |
| 树木、竹子、草丛、花簇 | Blender 制作可复用枝叶与少量变体 | 需要时使用修改器或 Geometry Nodes；独特老树、树桩可先试 Tripo 再整理。风动表现由 Godot 实现，不能假定 Blender 节点会在游戏中运行；密集植被还要检查透明叠加与阴影开销 |
| 陶缸、木箱、水桶、板凳、简单农具 | Blender | 回转、挤出和少量部件即可表达，便于统一材质与尺寸；篮筐编织等细节是否建几何取决于实际可见程度，不能因细节多就默认生成高面数模型 |
| 不规则观赏石、盘根树桩、复杂静态摆件 | Tripo 候选 → 按需 Blender 修整 | 适合先探索整体造型，再处理底部、穿插、面数和材质。小石块或简单轮廓仍可直接 Blender 制作；生成结果不合格时比较重建成本，不无限修补 |
| 猫、鸡、人物等需要活动的角色（若纳入范围） | Tripo 外观候选或 Blender 建模 → Blender 检查与修整 | 可试 Tripo 绑定与动作，但须验证实际体型、关节变形、脚底接触和循环；Godot 配置动画播放与行为。不能把静态好看或自动绑定成功当成动画可用，也不把四足或鸟类套成人形骨架 |
| 水面、涟漪、雨、雾、烟、选中轮廓、生长提示 | Godot 材质、动画或粒子等当前所需能力 | Blender 仅按需提供水岸、石头等承载几何；不把动态效果生成成静态实体。没有需求时不提前引入复杂特效系统 |
| 整座农场与可操作场景 | Godot 用组合场景组织独立资产 | 保留作物、地块、装饰的独立身份；不生成一个难以选中、替换和保存状态的整场景网格。Tripo 场景候选只能作为造型参考 |

同一类别允许例外：例如普通陶罐用 Blender，复杂雕花异形陶器可试 Tripo；固定远景建筑可接受整体模型，可开关门的近景建筑需要可控分件。依据是当前用途，不是工具偏好。

## Tripo 内部模型如何选

以下根据本机插件 0.2.2 的能力说明及 CLI 文档制定，属于候选选择规则，尚无本项目样本质量对比。运行时复核实际版本、参数和计费，不在此固定服务价格。[官方 CLI 说明](https://developers.tripo3d.ai/en/docs/cli)

| 模型 | 当前适用判断 | 需要留意 |
|---|---|---|
| P1（`tripo-p1`） | 倾向简洁轮廓、明确面数预算的独立道具候选 | 不把低多边形宣传等同于干净拓扑保证；仍检查轮廓、薄片、材质和可修改性。低面数不代表请求比 v3.1 更便宜 |
| v3.1（`tripo-v3.1`） | 更看重复杂轮廓、参考图细节或后续整理源模型时 | 为需要的细节付费；不要为小尺寸道具默认开启所有高清选项。需要较低面数时核对支持的简化方式及最终结果 |
| P2（`tripo-p2`，插件标为预览） | 只有确需其四边面输出等能力，且预期能减少编辑工作时小样评估 | 暂不作为默认；新版本、四边面或更高预算不保证变形布线、可编辑性和游戏效果更好 |

CLI 会因提示词含低多边形描述或 `face_limit ≤ 20000` 自动选择 P1。若本次判断需要 v3.1 并同时限制面数，应显式指定模型，避免参数改变了比较对象。不能因游戏运行在 Windows 就套用 `game-pc` 高预算预设，也不直接将 `game-mobile` 的预算当作项目标准。

输入方式：本项目正式外观候选优先先出图、再图转模型；纯文字生成仅用于不要求匹配既定外观的探索。多视图必须表现同一物件，不能混合不同设计。不要直接将整张场景图板当成一个道具输入，也不要假定自动补出的背面符合设计。具体准备方法见下节。

## 图片驱动的制作流程

2026-09-17 补充。运行画面和玩法入口见 [制作草案](production-brief.md)。已生成两张场景风格候选和一张修订后的单体输入示范；这只验证了参考图制作与目视筛选，尚未验证图转模型的输出质量。

### 两类图分别做什么

| 图的用途 | 需要呈现 | 不能拿它证明什么 |
|---|---|---|
| 运行界面参考 | 单张完整游戏画面、实际拟用镜头、作物与地块大小、最少必要 HUD；用于比较构图与风格 | 不证明功能已实现、模型结构正确或实际帧率；不能作为整场景网格输入 |
| 单体建模 / 生成参考 | 一个明确物件、完整轮廓、干净背景、适合观察结构的视角；用于 Blender 设计或 Tripo 输入 | 不证明背面、底面、真实尺寸、拓扑、UV 或绑定可用 |

先选少量同构图的运行画面比较风格，再把选定参考与固定的造型、材质、色彩约束共同用于单体图。重复相同风格词可以减少漂移，但不能替代共享参考图和逐张检查。场景里的物件如果被遮挡、裁切或透视严重，应单独重新生成；不直接裁下来当作完整资产图。

对于 Tripo 候选，先锁定单体外观再生成网格，有利于在较早阶段筛掉结构和风格错误。对于规则明确的 Blender 模块，可以直接按共同风格建模，必要时从体块渲染出结构参考；不要为了遵循流程给每块田地增加一次图片和三维生成。

### 单体参考图规范

下表中的画面占比与角度是本项目的起始建议，不是 Tripo 的接口限制；实际格式、尺寸、模型能力与输入数量在调用前核对当前 CLI / 官方接口文档。

| 维度 | 起始要求与检查方式 |
|---|---|
| 内容 | 一个独立资产或一个明确设计成整体的物件；不混入手、人物、花盆旁的地板、景观底座、文字、尺寸线、UI、其他备选款式。盆栽是否连盆必须由资产用途决定 |
| 结构 | 数清支脚、把手、叶片组等关键部件；接缝、孔洞、接地面和重心可信。薄片、细杆不能在图上断裂、融合或穿插；这些错误先修图或改用建模，不寄希望于重建自动纠正 |
| 背景 | 单一中性背景，与主体轮廓有足够对比；浅色物件不要融入白底。无地面纹理、场景、底座或强投影。不要把棋盘格画进图里冒充透明背景；需要透明时先核实输入支持 |
| 视角 | 通常用弱透视的三分之四视图，同时看清正面、侧面和少量顶部；约 10°～25° 俯视作为起点。避免过高俯视压扁高度，也避免广角夸张。资产视角不必等于游戏镜头 |
| 构图 | 整个物件完整入画，四周留白；主体约占画幅 70%～85%，不得切掉底部、把手或叶尖。优先方图、清晰轮廓，起始可用约 1024 像素或更高图；以工具实际支持为准 |
| 光照与色彩 | 中性、均匀、柔和，保持材质可辨；不要戏剧性明暗、强反射、景深或厚重调色。淡接触影可接受，但明显阴影可能被重建为几何或写入贴图，须在结果中检查 |
| 风格 | 固定主参考及文字约束，匹配轮廓夸张程度、材质粗糙感、细节密度和配色。提示词里的“game-ready”不能保证游戏资产质量 |
| 多视图 | 只有隐藏结构确实重要且本次工具支持时才增加；分别提供同一物体的正、侧、背等视图，保持尺寸、部件、颜色和光照一致。不要把拼贴板当成多张输入，也不要用互相矛盾的独立生成图 |

Tripo 官方建议突出单一清晰主体、完整轮廓、简洁背景和可辨认结构；三分之四视图是有用的单图起点，多视图可补充隐藏侧的信息，但仍需检查输出。上表对游戏用途和数值的取舍是项目建议。[单图准备指南](https://www.tripo3d.ai/blog/best-images-for-image-to-3d)、[多参考图说明](https://www.tripo3d.ai/blog/multiple-reference-images-3d-generation)

不同资产的重点不能全部压成同一个提示词：

| 资产 | 图像需要特别表达 | 制作取舍 |
|---|---|---|
| 罐、桶、篮等道具 | 开口、把手连接、底部；不可只给顶视图 | 简单回转和拼装结构优先 Blender；不可见的内部无需盲目细化 |
| 石头、树桩等不规则物件 | 整体连通关系、接地范围、主要突起，避免被读成多个物体 | 独特复杂轮廓可试 Tripo；简单石块直接建模可能更快 |
| 作物 | 确切品种、根部、叶片生长方向和阶段体积关系 | 各阶段分开清晰呈现，但用同一结构设计；Blender 共享部件或体块渲染比独立随机生成更利于连续性 |
| 建筑和拼接件 | 可见侧、屋顶关系、门窗位置；另用尺寸和模块约定控制接缝 | 图片只管外观，精确尺寸用建模约束；需要开关的门窗不能与主体焊死 |
| 需要活动的动物或人物 | 四肢彼此可区分、身体无遮挡、适合其物种的中性姿态 | 不一律套人形 T 姿势；须另外验证骨骼、关节变形与动作，不靠静态图验收 |

需要可靠多视图时，可先在 Blender 做低成本结构体块，再用同一体块渲染不同方向；图片生成用于风格探索。这样结构有同一来源，不让互相矛盾的正背图进入重建。

### 提示词如何组织

使用“固定风格段 + 本次物件段 + 输入画面要求”三段；提交参考图时注明它负责风格还是结构。以下是图片生成提示词的模板，不是 Tripo 参数，也不保证图转模型接口接受额外文字修改：

```text
Style: a coherent stylized 3D Jiangnan miniature game asset; softly rounded
silhouette, broad readable forms, matte natural materials, restrained
celadon / moss / ivory / slate / warm-earth palette, sparse surface detail.
Use the supplied style reference for materials and shape language only.

Object: exactly one [物件、品种、部件数量与连接关系].
Its silhouette, contact area and proportions are [具体结构要求].
Include [必要部件]; exclude [本次容易混入的物体].

View: complete object, three-quarter view, weak perspective, modestly
above the object, all contours sharp, centered with a clean margin.
Plain neutral contrasting background, soft neutral diffuse light,
minimal contact shadow. No scene, pedestal, text, UI, collage,
cropped parts, extra objects, depth of field or dramatic shadows.
```

给模板填具体结构，不要不断堆“高质量、超精细、4K”形容词。正面结构已经锁定时，后续修改优先基于同一图编辑并明确只改哪一项；每次仍检查结构有没有随风格修改而漂移。本轮的实际完整提示词及参考关系在 [生成记录](visual-references/generation-record.json)。

### 从好看的图到游戏资产

图像检查通过后，才为明确的三维候选提交请求。根据当前工具能力明确是否生成纹理、目标面数与模型版本；保存真实用量，不默认开启所有高清和后处理选项。

拿到模型后要检查：轮廓是否匹配、背面和底面是否合理、部件是否意外粘连；实际三角形数、UV、法线、材质槽和贴图是否合适；大小、朝向、枢轴能否正确摆放。碰撞、作物状态、交互和动画由游戏需要决定，不能假定生成模型自带。需要昼夜变化时重点检查贴图是否带有不应固定的强阴影或高光。

最终将 GLB 放入 Godot，以目标镜头、显示大小和代表性同屏数量检查。没有可见收益时不增加微小几何、贴图尺寸或材质槽；不为所有资产一律要求 LOD、重拓扑或动画。导入成功、静态预览好看、图片标注“游戏资产”，都不能替代这一步。

### 本轮得到的可复用经验

- 运行画面比较保持布局一致，比同时改变镜头、内容和画风更容易判断偏好。实际生成仍可能改变细节，应检查田格数、作物状态与交互区，而不是把提示词当作输出事实。
- 石头首图的“三个鼓包”形成近似叠石的分缝；修订为单一连续体后才得到清楚的单物件轮廓。遇到结构歧义先修输入，修图后仍不代表隐藏面或网格已验证。
- 作物图可能把“白菜”画成圆白菜；需要明确品种和叶型。原图有多株幼苗也不应改变“一格一个玩法状态”的设计。
- 这些经验来自本轮图片生成与目视检查，尚无 Tripo 三维输出和 Godot 画面对应证据。后续取得实际结果后在这里更新，不将单次成功推广成所有生成的保证。

## 工具之间怎样交接

1. **先定义用途。** 在当前任务中说明资产的显示大小、预计同时出现数量、是否拼接、是否动画或分阶段、需要修改的部件；不为每个小道具建立额外审批文件。没有这些依据时先做体块，不先锁死全项目面数预算。
2. **制作可维护的源资产。** Blender 自制的部件直接复用；Tripo 结果保留原始文件、任务 ID、模型版本、输入与参数及实际积分用量。修整另存，已采用资产保留必要来源及使用依据；凭据不入库。
3. **用 Blender 处理确有需要的修整。** 校正尺寸、朝向和枢轴，检查法线、穿插、UV、材质、骨架或阶段关系；简单合格资产不强制重拓扑。若修整已接近重新建模，切换制作方式。修改优先回到源文件，避免下次导出丢失修正。
4. **明确导出物。** 当前优先显式导出 GLB / glTF 2.0；`.blend` 保留在 `ArtSource/`，不放入 `Game/`。Tripo 的合格 GLB 可直接作为导入候选，不必为 Godot 额外付费转 FBX；需要修整时在 Blender 编辑再导出。Godot 支持直接导入 `.blend`，但会依赖本机 Blender 转换，本项目当前关闭该入口。程序材质、修改器、骨架与动画的保留情况按实际导出物检查。[官方格式说明](https://docs.godotengine.org/en/4.7/tutorials/assets_pipeline/importing_3d_scenes/available_formats.html)
5. **在 Godot 完成游戏资产。** 用可编辑 `.tscn` 场景组合导入模型、脚本与必要碰撞，不直接改生成缓存；重导入后复查引用。材质适配当前渲染器，不假定 Blender 节点或生成贴图会得到完全相同效果。保留资产旁的 `.import` 设置，避免下一次导入覆盖调整。
6. **在目标画面验收。** 使用当前获准的镜头和窗口大小，检查可辨识度、风格、摆放和遮挡；阶段资产切换检查根部位置，动画检查变形，拼接件检查接缝。涉及夜间时检查暗处可读性。需要的性能验证在代表性同屏数量下进行，不能只看单个模型的漂亮预览。

模型尺寸以可核对的尺度参照统一，采用 Godot 3D 的米制尺度约定；导出与导入后核对实际包围盒、轴向和摆放。[3D 入门](https://docs.godotengine.org/en/4.7/tutorials/3d/introduction_to_3d.html)。道具通常以接地位置作为摆放枢轴，门以铰链、模块以约定连接点为准，不对所有模型机械套用“底部中心”。具体格子大小由玩法决定。

统计统一看最终导入网格的三角形数，区分 Blender 多边形数、生成服务参数和 Godot 实际结果；同时记录有影响的材质槽、贴图尺寸、骨骼与同屏数量。先做可辨认的轮廓和温润材质，再决定微小细节；不预设所有资产都要 LOD、4K 贴图或完整 PBR 贴图组。

## 什么时候测试，什么时候请用户判断

工具分工可以先由上述结构约束确定，不必先付费。2026-09-17 已核验文档与既有证据，并使用图片生成工具制作视觉参考；尚未提交 Tripo 生成请求，未消耗 Tripo 积分。图片生成不等于免费，也不计作三维生成验收。

当具体资产出现选择疑问时，用一个代表性小样回答一个问题。例如“Tripo 的盘根树桩是否比 Blender 直接制作更省修整时间”，应记录实际积分、处理耗时、修整量与 Godot 画面，而非只比较生成速度。当前已有小规模真实付费测试授权；执行时说明本轮对象、调用次数及依据当时价格确定的积分上限，在该范围内推进，不逐步重复索权，也不外推为批量生产或无限重生成授权。参数不匹配或任务状态不明时先查原任务，避免重复扣费。

第一次验证生成资产时，优先选择一个复杂但独立的静态装饰，完成生成、检查、必要修整、导出与 Godot 导入的完整小样；不从多阶段作物或活动角色开始。只有具体需要比较 P1 / v3.1，才为同一参考增加另一个模型样本；其结论只覆盖该样本和测试条件。

技术可用性由开发侧检查；需要用户判断的是目标画风与喜好。首次准备成批制作某一风格时，给用户看同一 Godot 镜头、光照和显示尺寸下的少量代表样本，明确询问轮廓是否足够可爱、材质是否温润、细节是否过密、是否符合江南微缩田园。工具官网预览不能替代这次判断。风格确定后的常规变体按已有标准推进，不逐件要求审批。

当前无需用户先决定技术参数。进入首个可玩切片时，建议先用 Godot 体块验证构图与点选，再用 Blender 做一种作物及对应地块；如果本次切片确实需要复杂装饰，再加入一个 Tripo 候选。该顺序不预先批准作物种类、装饰数量或动物系统。
