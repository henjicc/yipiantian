# 田园三维资产生产与留档

适用于“我有一片田”项目。先辨认任务是新资产制作、已有模型修复，还是视频素材检索；按对应入口读取，不为查询素材重新生成模型。本技能是流程入口，详细参数与既有事实在下面的项目文档维护。

## 先找到当前资产和流程

- 新生成／替换：读 [资产工作流](../../../docs/asset-workflow.md) 的工具交接与留档要求，再读 [Tripo 工作流](../../../docs/tripo-workflow.md) 中本次需要的模型、纹理、分件或动画条目。
- 减面、破面、细节损失：先读 [LOD 与破面验收](../../../docs/asset-workflow.md#lod-与破面验收)，沿原模→整理导出→引擎导入→运行时逐层定位。
- 树木拆件／动画：读 [树木制作记录](../../../ArtSource/Environment/Trees/README.md) 和 Tripo 工作流的树木动画章节；其他资产先找其 `ArtSource/` README 与生成记录。
- 找视频素材／补拍对比：先读资产 README 的视频节点，再查 [制作留档入口](../../../制作留档/README.md)、[剪辑索引](../../../制作留档/04_报告与视频素材/03_成品与制作过程剪辑索引.md) 和 [录屏索引](../../../制作留档/05_开发录屏/录屏索引.md)。本地留档不随 Git 同步，缺失时按源文件与记录恢复可补拍部分，不声称录像仍在。

## 制作时必须守住的边界

1. **新 Tripo 生成必须先用图片工具出参考图并检查，再图生模型。** 不同形态分别出图；需要多视图时保持物件一致。已有合格参考与原模可复用，修复或补拍不强制再付费生成。
2. 几何、纹理与后处理分别选型；显式记录精确版本、质量档、面数预算、关键开关、服务回显、任务 ID、输入输出、实际费用与采用状态。复用已核验契约，仅对版本变化或未知能力补查官方资料；任务状态不明先查原任务，避免重复扣费。
3. 原始参考、原模和云端分件保持不可变，整理在副本进行。保留可编辑源、现役重建入口和审计，区分请求面数、实际三角数与运行时绘制量；四边面源和游戏三角化输出分别保存。
4. 分件结果只提供区域，**不等于骨骼、关节枢轴或无缝动画**。核验尺度、原点、切口、UV 与材质损失；连续枝干优先保持连续变形，需要真实关节才设计骨架。Tripo 自动绑定先检查实际体型兼容性，不支持时选择本地方案并如实记录。落叶作为独立、有界的效果制作。
5. 不以统一减面比例牺牲轮廓。GLB 的 UV 拆点不必然是洞；对工作副本按几何位置审计，减面前按需处理接缝并保留面角 UV、权重和材质边界，导出后重导入复核。不要对原模盲目合点、补洞或重算法线。
6. 不把非选中模型统一设为 `lod_bias=0`；不对未经检查的人工低档叠加自动减面。普通静态资产可采用经过验收的 Godot 自动 LOD，近景主体、薄叶和动画资产按实测选择人工档或单件禁用。检查近→远→回近、背面、边缘和运动接缝，不能只增加面数或全局关闭 LOD 掩盖原因。
7. 正式接入后确认运行中确实引用新资源；检查相邻模块穿模、接地、遮挡及相关昼夜视角。动态物体覆盖运动范围，复用项目相关测试；单体渲染和编译成功不能替代实景检查。

## 制作节点与后续视频

在完整制作单元结束时按 [资产留档要求](../../../docs/asset-workflow.md#本地制作留档) 补齐来源链；重大节点在资产 README 留一个可检索的节点名／日期、代码基线和素材入口。具体示例见 [桂花与 LOD 视频节点](../../../ArtSource/Environment/Trees/README.md#视频节点20260917-osmanthus-lod)。

将用户需要的链路关联起来：**参考图 → 原始模型及转角展示 → 分件着色／拆解展示 → 整理与动态 → 游戏最终效果**。每阶段标记已有图片、已有视频、已有源但待补拍或原件缺失；指明准确文件、用途及输入版本。失败与旧版证据单独标记，不被最终输出覆盖。

需要前后对比时，尽量固定相机、光照、尺度与动作相位；不同树形、机位或光照的历史录像只能作过程回顾，不当作单变量 LOD 对照。源文件补渲染标为“按保存源文件重现”，分件爆炸动画标为“分件可视化”，不能冒充当时操作录屏或 Tripo 自动绑定成果。

本地留档目录仅保存一份素材并建立链接索引，不为索引重复拷贝大文件，不把本地存档说成已备份到远端。只有用户要求补拍或达到 [关键节点录屏](../../../rules/testing.md#关键节点录屏) 条件才录制；找素材和整理规则不自动重拍整条视频。

## 交付

总结实际采用版本、游戏位置、验证与限制，更新资产记录、节点入口及需要维护的规则。按项目测试和 Git 约定完成交付；保留已就绪的最新游戏预览，或启动最新游戏，静音、右侧第二屏。工具贡献、实际费用、用户主观验收和未拍镜头分别说明，不虚构成功。
